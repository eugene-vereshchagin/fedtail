# Как писать ленты

Лента в fedtail — это правило: какие посты (и какие события Активности) в неё попадают.
Каждая лента встроенных наборов — такое же правило, теми же словами, поэтому всё, что умеет
лента набора, умеет и своя, а ленту набора можно поменять.

На этой странице — весь словарь: как устроено правило, все ключи, все слова каждого ключа.
Слова — fedtail, не сервера: они проверяются при чтении конфига, и незнакомое слово никогда
молча не отбирает «ничего» — у ленты появляется предупреждение.

## Где делаются ленты

- **≡ → «Ленты…»** (или правый щелчок по ленте → «Изменить ленту…») — редактор лент, в
  каждом интерфейсе. Порядок, какие показаны, у каждой — название, картинка, источники и
  условия; пишется в `config.toml` сразу и подхватывается работающей программой.
- **`config.toml`** руками — таблица `[[lanes.custom]]` на ленту. Редактор пишет те же
  таблицы, так что они никогда не расходятся.

Лента набора, изменённая в редакторе, становится своей: `[[lanes.custom]]` с тем же именем
на её месте. «Как в наборе» убирает свою версию обратно. Из какого набора ленты —
`lanes.preset`; какие из его лент включены — `lanes.enabled` (см. [настройки](/docs/ru/config.md)).

## Как работает правило

```toml
[[lanes.custom]]
name = "pics"                     # слово ленты: латиница, цифры, _ и -
title = { ru = "Картинки", en = "Pictures" }
any = [                           # берёт пост, подходящий под ЛЮБОЕ из условий…
  { author = "followed", has = "image" },
  { source = "tags:photography" },
]
none = [{ has = "sensitive" }]    # …и не пускает подходящий под любое из этих
```

- **`any`** — условия, которые берут пост. Достаточно одного.
- **`none`** — условия, которые не пускают пост, даже если `any` его взяло.
- **Условие** — таблица ключей: подходит, когда подходит **каждый** ключ («и»). Список слов
  в ключе — **любое** из них: `author = ["followed", "mutual"]`.
- **«Или» внутри условия** — его собственное `any`, список таблиц, одна из которых тоже
  должна подойти: `{ author = "followed", any = [{ has = "image" }, { kind = "reply" }] }` —
  картинки или ответы тех, на кого подписан.
- **`source`** ленты сужает каждое условие до этих источников; без него fedtail сам
  выбирает источники, которые могут принести то, о чём спрашивают условия (условие об ответах
  тебе читает упоминания, о тегах — теги).
- **Пост, который не взяла ни одна лента**, попадает в «Неразобранное»: правило никогда не
  теряет пост.

Лента событий — `event = "favourite"` и подобные — показывает строки Активности среди своих
постов, по тихой строке на каждую («bob, ann — ★ лайкнули · 14:20 · «пост»»); лента из одних
событий — лента вроде Активности, её события непрочитаны, пока не увидены.

## Условие одной строкой

Редактор пишет условие строкой, и так же его можно набрать:

```
author: me, followed; kind: post          запятая — любое из них
text: tbilisi + georgia, грузия            в text «+» — все вместе в одной группе
any: [has: image] [kind: reply]            «или» внутри
*                                          каждый пост (ни о чём не спрашивает)
```

То же в `config.toml`: `{ author = ["me", "followed"], kind = "post" }`,
`{ text = [["tbilisi", "georgia"], ["грузия"]] }`.

## Быстрые фильтры над лентой

Над лентой кнопки двух родов; ни те, ни другие не меняют, что лента берёт, — только что из
этого видно:

- **Свои у ленты** — `switches = ["posts_only", "unread_only"]`: «Всё / Только посты /
  Новое». `switches = []` — никаких. Без ключа fedtail решает, как раньше: «Только посты» там,
  где лента читает свои источники, «Новое» — где она отмечает прочитанное.
- **У условия** — `switch = "Комменты"` на условии делает кнопку с этим словом, которая
  показывает только взятое этим условием; `shown = false` — эти посты спрятаны, пока кнопку не
  нажмут:

```toml
any = [
  { source = "home", kind = "post" },
  { source = "home", kind = "reply", switch = "Комменты", shown = false },
]
```

## Правильно ли?

- Меню поста → **«Почему это здесь?»** — какое условие его взяло и что не пустило его в
  другие ленты.
- `python3 -m fedtail --explain-lane ИМЯ` — что правило ленты делает со всем, что хранится.
- Незнакомое правилу слово, опечатка в ключе, условие, которое ни один сервер не наполнит
  (посты «для подписчиков» от чужих), — предупреждение в редакторе и в `--explain-lane`;
  условие с незнакомым словом не берёт ничего, остальная лента работает.

## Примеры

```toml
[[lanes.custom]]                  # Лента с подписанными тредами; комменты за кнопкой
name = "home_plus"
title = "Лента"
any = [
  { source = "home", kind = "post" },
  { source = "subs" },
  { source = "home", kind = "reply", switch = "Комменты", shown = false },
]

[[lanes.custom]]                  # что пропустил за ночь, по человеку
name = "overnight"
mode = "catch_up"
window = "10h"
bundle = "author"
per_author = 3
any = [{ author = "followed", kind = ["post", "quote"] }]

[[lanes.custom]]                  # лучшее на моём сервере за сутки, самые лайкнутые первыми
name = "local_best"
sort = "likes"
read = "browse"
any = [{ source = "local", age = "<1d", likes = ">5" }]

[[lanes.custom]]                  # поездка: посты о Грузии, до её конца
name = "trip"
icon = "plane"
any = [{ text = [["tbilisi"], ["georgia"], ["грузия"]], until = "2026-11-20" }]
none = [{ kind = "boost", age = ">2d", age_of = "original" }]

[[lanes.custom]]                  # лайки и бусты моих постов рядом с моими постами
name = "mine"
any = [{ author = "me" },
       { event = ["favourite", "reblog"], switch = "лайки" }]
```
