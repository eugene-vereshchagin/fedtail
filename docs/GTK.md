# fedtail: GTK-фронтенд

Статус: **черновик плана, 21 окт 2026**. Этап 0 начат (`palette.py`, `pango.py`), каркас (этап 1)
готов; остальное по очереди. По мере готовности устройство переезжает в ARCHITECTURE.md (§14 — Qt, будет §14a — GTK).

## Зачем и для кого

Qt — родное KDE-приложение. GTK — для «гномоводов»: GNOME, Cinnamon, MATE, XFCE, Budgie,
чтобы fedtail там выглядел своим, а не KDE-гостем. Принципы те же: ничего не прыгает,
у каждого ответа виден родитель, всё поведение — флаги в конфиге, окна настроек нет.
Фронтенд выбирается `ui.frontend = "gtk"` или `fedtail --ui gtk`.

## Стек

| что | выбор | почему |
|---|---|---|
| тулкит | **GTK 4** через PyGObject | GTK 3 доживает; в Debian 13 GTK 4.18 |
| libadwaita | **по возможности, не обязательно** (`ui.adwaita = auto / on / off`) | в GNOME без неё «не родное», в XFCE/MATE/Cinnamon с ней — наоборот чужое; без неё фронтенд обязан работать |
| минимальные версии | GTK ≥ 4.10, libadwaita ≥ 1.4 (если есть) | Debian 12 — 4.8, слишком стар; Ubuntu 24.04 — 4.14 и Adw 1.5; Debian 13 — 4.18 и Adw 1.7 |
| пакеты Debian 13 | `python3-gi gir1.2-gtk-4.0` (+ `gir1.2-adw-1`) | войдут в «Рекомендует» deb-пакета, не в «Зависит» |
| Windows | **не делаем** | GTK под Windows — MSYS2 и боль; там остаётся Qt |

## Что уже есть и годится как есть

Ядро и `core/view.View` (модель, не JSON сервера), `richtext` (санитайзер), `themefile` (темы
без Qt), `helpdocs`, `notifytext`, `fedstatus`, `iconart`, `core/commands`, `model.text`,
`View.roster()`. Протокольный слой (этапы 0–4 PROTOCOLS.md) — ровно то, что нужно: GTK
сразу пишется на модели, сырых данных не видит.

## Главная проблема: логика, застрявшая в Qt

Разбор `frontends/qt/` показал: из ~16 000 строк примерно **2 700–3 000 — не Qt**, а
решения «что показать и что сделать», живущие внутри виджетов. Без выноса GTK их
скопирует, и два фронтенда начнут расходиться в поведении. Кандидаты, по размеру:

| что | где сейчас | строк | куда |
|---|---|---|---|
| кэш картинок: LRU в байтах, очередь «новые первыми, но без голодания», повторы, чистка диска | `qt/images.py` | ~400 | `common/images.py` ✓ (декодер, размер, «на экран» и таймер — у тулкита: `qt/images.py`, `gtk/images.py`) |
| сборка карточек ленты/треда/профиля, разделитель «новое ниже», стартовая позиция, фильтры, «прочитано» | `qt/feed.py`, `qt/card.py` (`CardSpec`, `make_spec`) | ~450 | `common/lane.py` ✓ (Qt и GTK на нём: фильтры, беседы, воронка медиа, «прочитано») |
| меню поста и кнопки: какие действия, когда, с какой ссылкой `fedtail:` | `qt/card.py` `_fill_more`, `_actions` | ~150 | `common/actions.py` ✓ (Qt на нём) |
| разбор ссылок `fedtail:<действие>/<арг>` | `qt/window.py` `on_link` | ~90 | `common/links.py` ✓ (Qt на нём; подтверждения — хуком окна) |
| правила «написать»: ключ черновика, видимость ответа, упоминания, CW, счётчик, автодополнение | `qt/compose.py`, `qt/dock.py` | ~260 | `common/compose.py` ✓ (Qt на нём) |
| цвета темы: «auto» из палитры, FOLLOWS/TINTS, смешивание, контраст | `qt/theme.py` | ~150 | `frontends/palette.py` ✓ (Qt на нём) |
| командная строка Point | `qt/cmdline.py` (почти копия `tui/model.Commands`) | ~110 | `common/commands.py` ✓ (Qt, TUI, веб на нём) |
| правила split: строка ввода (куда уйдёт, кто увидит), вкладки, лицо под курсором | `qt/dock.py`, `qt/roster.py`, `qt/window.py` | ~130 | `common/split.py` ✓, `common/roster.py` ✓ (Qt на них; GTK — на этапе 6) |
| группировка и слова «Активности» | `qt/feed.py` | ~80 | `common/activity.py` ✓ (Qt на нём) |
| поиск, бейджи/свёртка сайдбара, решения уведомлений | `find.py`, `window.py`, `notify.py` | ~270 | `common/find.py` ✓, `common/sidebar.py` ✓ (GTK сворачивает разделы), `notifytext.due` ✓ |
| обработка результатов моста; страница сервера, таблица проверки, правка профиля; объявления, фильтры, заглушенные — на модели | `bridge.py`, `social.py`, `profile.py`, `announce.py`, `silence.py` | ~200 | `common/results.py` ✓, `common/server.py` ✓, `common/announce.py` ✓; `model.WordFilter`, `Silenced`, `Announcement` ✓ |

**Как делаем:** выносим по одному; Qt переводится на общий модуль в том же заходе. Решения
проверяются в `tests/test_common.py` без тулкита; Qt-смоук — локально у тебя (в песочнице
PySide6 нет). Общее не импортирует тулкит — это проверяет тест. В Qt остаётся то, что про
виджеты: раскладка, вкладки окна сообщений (`MessageTabs.sync`), рисование.

Попутно найденные утечки, которые надо закрыть до копирования: `qt/silence.py` и
`qt/announce.py` читают сырые словари сервера; `View.read_ids` лезет в `_core.store`;
`richtext.plain_tip` заворачивает в Qt-шный `<qt>…</qt>`; в ARCHITECTURE §13 не описаны
события `arrived`, `thread_grew`, `rate_limited`, `capabilities_changed`, `prefetch`,
`prefetch_video`.

## Проблемы GTK и решения

| проблема | решение |
|---|---|
| **Текст поста.** Qt рисует HTML-подмножество в QLabel; GTK понимает только Pango-разметку: нет `<p>`, `<br>`, `<blockquote>`, `<ul>`, нет стилей у ссылок | `frontends/pango.py` ✓: санитайзерный HTML → Pango (абзацы — пустой строкой, цитата — `▎` и курсив, списки — `•`/номера, `<code>` → `<tt>`); ссылки остаются `<a href>`, Gtk.Label их ловит сигналом `activate-link` |
| **Темы.** QSS у Qt генерируется целиком; у GTK — CSS с другими селекторами | цвета считает общий `palette.py`, а `gtk/theme.py` пишет из них свой CSS (классы `.ft-card`, `.ft-unread`…). Ключи тем те же, файлы тем общие |
| **«auto»-цвета.** В GTK 4 нет API палитры рабочего стола (как `QPalette`) | светлая/тёмная — из `Adw.StyleManager` или `gtk-application-prefer-dark-theme`; акцент — из Adw ≥ 1.6 (`get_accent_color_rgba`), иначе адвайтовский синий; база — эталонные цвета Adwaita light/dark. Тема «system» на GTK значит «как Adwaita» |
| **«Ничего не прыгает».** Qt держит свою колонку со своей математикой окна прокрутки | лента — `Gtk.ListBox` в `ScrolledWindow`, строки по ключу, на экране ничего не пересобирается: новые дописываются в конец (`oldest_first` — по умолчанию), «Старше» вставляет сверху и сдвигает прокрутку на прибавку высоты. Для `newest_first` — то же зеркально. Длинные ленты потом — `Gtk.ListView` с моделью (виртуализация), когда упрёмся |
| **Прочитанное.** Qt считает «увидел» по геометрии карточек | тот же предикат (вынести из `feed._emit_seen` в функцию от верх/низ карточки и окна), GTK зовёт его по `value-changed` прокрутки |
| **Потоки.** Ядро зовёт колбэки из своих потоков | `gtk/bridge.py` ✓: `GLib.idle_add` — аналог очереди сигналов Qt, та же классификация ошибок |
| **Трей.** В GTK 4 трея нет, в GNOME его нет вообще | `StatusNotifierItem` по D-Bus через Gio, если есть хост (KDE, XFCE, Cinnamon, GNOME с AppIndicator); нет хоста — `ui.close_to_tray` честно не работает, это пишется в лог |
| **Уведомления** | `Gio.Notification` через приложение (родное для GNOME, с кнопкой «Открыть»), `notify-send` — запасной путь, решения «когда» — общие с Qt |
| **Один экземпляр** | у fedtail свой сокет (`SingleInstance`) — `Gtk.Application` ставим с `NON_UNIQUE`, чтобы не спорили |
| **Видео** | `Gtk.Video` (GStreamer) есть из коробки; нет GStreamer-плагинов — «открыть снаружи» |
| **Картинки** | декод `GdkPixbuf`/`Gdk.Texture.new_from_bytes` в рабочем потоке, `Gdk.Texture` потокобезопасна (в отличие от QPixmap); кэш — общий модуль |
| **Раскладка «split» (QIP)** | на Qt сделана; на GTK — после обычной раскладки, на том же `View.roster()` |
| **Проверка без экрана** | в CI (Debian 13) — `xvfb-run`; `tests/test_gtk_smoke.py` гоняет окно на фейковом сервере, `tools/gtk_screenshots.py` снимает его через `Gtk.WidgetPaintable` → PNG (без оконного менеджера) |
| **Значок в панели задач** | `GApplication` требует id с точкой; на Wayland значок ищется по id. Id — `online.dmesg.fedtail`, `.desktop` назван так же; на X11 — `prgname` «fedtail» под `StartupWMClass` |

## Решения (21 окт 2026)

1. libadwaita — есть, используем; нет — работаем без неё (`ui.adwaita = "auto"`, `on`/`off`
   форсируют).
2. Тема «system» на GTK — «как Adwaita».
3. GTK под Windows не делаем: там Qt.
4. Порядок этапов 2–6 — пока как в таблице.
5. Id приложения — `online.dmesg.fedtail` (по сайту fedtail.dmesg.online), `version.APP_ID`;
   `.desktop` переименован под него для обоих тулкитов, при каждом запуске окна запись и
   значок проверяются и чинятся, старая `fedtail.desktop` убирается (`ui.desktop_entry`).

## Что проверено, а что нет (21 окт 2026)

В песочнице, где это писалось, был GTK 4.14 (как в Ubuntu 24.04) без libadwaita и без
PySide6. Проверено: все тесты (Qt-шные пропущены), GTK-смоук под Xvfb, скриншоты тем
system / point / terminal, светлых и тёмных. **Не** проверено: с libadwaita (`ui.adwaita =
"auto"` у тебя её найдёт — первым делом смотреть туда), GTK 4.18 из Debian 13, Wayland,
сравнение цветов с Qt (`tests/test_palette.py::SameAsQtTest` — побежит в CI).
Qt-фронтенд этой пачкой не тронут ни строкой; в ядре — одно: `View.on` переводит payload
событий в модель через новый `View.event_payload` (поведение то же, им пользуется GTK-мост).
