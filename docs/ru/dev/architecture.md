## 1. Что такое fedtail

Десктопный клиент федиверса (GoToSocial, Mastodon, Akkoma — всё, что говорит на REST API
Mastodon), написан на Python. Его смысл — **контекст**: люди отвлекаются на пост и
возвращаются, не помня, о чём был разговор. Поэтому каждый ответ показывает, на что он
отвечает, под комментарием виден твой собственный ответ, треды открываются деревом на том
посте, откуда ты пришёл, а ленты помнят, где ты остановился, и никогда не прыгают. Он
наследует Point.im и Juick.

Принципы, которые определяют код (из design.md):

* **Ничего не прыгает.** Новые посты никогда не сдвигают то, что ты читаешь.
* **Каждый ответ знает своего родителя.** Над каждым ответом — цитата родителя.
* **Ленты раздельны.** Лента, боты, ответы мне, прочие упоминания, …
* **Приватно по умолчанию.** Новый пост идёт подписчикам; ответ никогда не публичнее
  родителя.
* **Всё поведение — флаги в конфиг-файле.** Окна настроек нет и не будет. (Данные на
  сервере, например свой профиль, правятся в диалоге: это не настройка клиента.)
* **Ядро ничего не знает про GUI.** Фронтенды — плагины; Qt был первым.
* **Один процесс = один аккаунт.** Второй аккаунт — второй профиль.

## 3. Как он запускается

`python3 -m fedtail [--profile ИМЯ] …` → `fedtail/__main__.py:main()`:

1. Разбор флагов. `--install-desktop` сразу выходит.
2. `paths.resolve(profile, config, data)`: файл конфига
   `~/.config/fedtail/<profile>/config.toml`, папка данных
   `~/.local/share/fedtail/<profile>/` (0700). Переопределяется `--config/--data`.
3. `config.load()` → проверенный словарь `cfg` (см. §16). Сломанный конфиг печатает
   причину и выходит с кодом 2.
4. Пишет `config.example.ru.toml` и `config.example.en.toml` рядом с конфигом пользователя
   (всегда текущий справочник; старый одноязычный `config.example.toml` уходит), выбирает
   тот, что на языке файла пользователя (`config.language_of`), и сообщает об опциях, которых в файле пользователя ещё нет;
   `--update-config` вставляет их и выходит.
5. `--bug-report` упаковывает журналы (§18) и выходит.
6. `i18n.setup(cfg.ui.language)`.
7. `SingleInstance`: если другой процесс этого профиля отвечает на своём unix-сокете,
   его просят поднять окно, а мы выходим.
8. `diag.setup()` — файл журнала, файлы падений и стеков, перехватчики исключений — потом
   шапка сессии и поток статистики.
9. `frontends.load(name)` импортирует модуль фронтенда; `Core(cfg, paths)` открывает
   хранилище и создаёт пулы потоков (сети пока нет).
    Команда в терминале (`fedtail show replies`) останавливается до блокировки:
    `__main__._terminal()` → `cli.run(core, argv)`, которая подключается, делает один
    опрос, печатает и уходит.
10. `frontend.run(core, instance, argv)` — для Qt (`frontends/qt/__init__.py`):
    QApplication → `theme.apply()` → `Bridge(core)` → `MainWindow` →
    `diagnostics.install()` → `win.show()` → `win.start()`.
11. `MainWindow.start()`: нет токена → `LoginDialog` (OAuth OOB: браузер показывает
    код, пользователь его вставляет). Потом `core.connect()` (в пуле): проверить
    аккаунт, прочитать возможности сервера, собрать источники, прочитать списки → `ready`.
    `_connected()` заполняет боковую панель, выбирает последнюю ленту, и
    `core.start_polling()` запускает поток опроса.

## 4. Потоки и правила, которые их разводят

| поток | что в нём работает |
|---|---|
| GUI (главный) | все объекты Qt; слоты Bridge; никогда не ждёт сеть |
| `fedtail-poll` | `Core._poll_loop`: `poll_once()` раз в `poll.interval_seconds` или когда разбудят (`poll_now()`) |
| `fedtail-stream` | `protocols/mastodon/stream.py`: поток WebSocket сервера (`poll.stream`); `update` / `notification` только зовут `poll_now()` — забирает всё равно опрос, так что оборванный поток ничего не теряет; переподключение с паузой 5 с…5 мин; токен идёт в заголовках рукопожатия, никогда в URL или в журнал |
| пул `fedtail_*` (4) | действия пользователя: пост, лайк, открыть тред, профиль… (`core.submit`) |
| пул `fedtail-bg` (2) | фоновая работа: родители, «ответил ли я?», подписки по запросу, честные счётчики |
| пул `fedtail-img` (4) | загрузка и сохранение картинок (в `Images`) — очередь аватаров никогда не задерживает отправку поста |
| `fedtail-instance` | сокет единственного экземпляра |
| `fedtail-stats`, `fedtail-watchdog` | диагностика (§18) |

Правила:

* **Ядро никогда не импортирует Qt.** Оно возвращает `concurrent.futures.Future` и
  излучает события. Всё, что связано с Qt, живёт в `frontends/qt`.
* **Объекты Qt трогают только в GUI-потоке.** `Bridge.call(future, ok, fail)` выполняет
  обработчики в GUI-потоке (через сигнал с очередью). События ядра приходят через
  `Bridge.event` (тоже с очередью). `QImage` можно строить в рабочих потоках
  (images.py так и делает), `QPixmap` — только в GUI-потоке.
* **У хранилища одно соединение SQLite под `RLock`.** Каждый метод берёт блокировку на
  короткую транзакцию (`with self._tx()` для записи). Режим WAL.
* `Core.poll_once` держит `_poll_lock`, так что опросы не пересекаются, а при выходе
  хранилище закрывается только после остановки опроса.
* Виджет может быть удалён, пока фьючерс ещё в пути: обработчики, которые трогают виджет,
  ловят `RuntimeError("…already deleted")` (Bridge делает это централизованно).

## 5. Данные: объекты Mastodon, id, порядок

* Статусы и аккаунты хранятся как **JSON-словари сервера**, без изменений. Классов модели
  нет. `model.real(st)` для буста возвращает бустнутый статус, иначе сам статус — зови его
  всякий раз, когда имеешь в виду «пост».
* Id — непрозрачные строки: GoToSocial использует ULID, Mastodon — snowflake. Никогда не
  сравнивай id как числа. Для порядка `store.sort_key(created_at, id)` строит
  `"<время iso>|<id, дополненный слева до 32>"`, это сортируется по времени для обоих.
* **Короткий id** (`#a3f` как на Point): с 0.18 выводится из id поста (`#kq3zt`,
  `store.short_code`, таблица `short_ids`), одинаковый на всех устройствах; имена, которые
  раньше выдал счётчик (таблица `aliases`, `a00`…`zzz`, потом 4 знака), остаются со
  своими постами (§12).
* `in_reply_to_account_id == me` значит «ответ мне» (`model.is_comment_to_me`).
* Боты: `account.bot` или перечисленные в `lanes.extra_bots`.

## 6. Хранилище (SQLite, `state.db` в папке данных)

| таблица | что хранит |
|---|---|
| `statuses(id, data, created_at, reply_to, author, touched)` | виденные статусы, JSON; столбцы `reply_to`/`author` — для быстрого «мои ответы на X»; `touched` — когда сохранён в последний раз (время милости для gc) |
| `items(source, item_id, status_id, sort)` | записи каждого источника (лента — список элементов, указывающих на статусы; упоминания используют id уведомлений) |
| `read(status_id)` | отметки о прочтении |
| `missing(status_id)` | родители, которые сервер не отдал (404/403/410) — показываются как «пост недоступен» |
| `drafts(key, data, updated)` | черновики; ключ `new` или `reply:<id>` |
| `aliases(n, status_id)` | короткие id, выданные счётчиком (до 0.18) |
| `short_ids(code, status_id)` | выведенные короткие id: полный 8-значный код → пост |
| `sync_out(seq, op)` | записанные операции синхронизации, ещё не отправленные (core/sync) |
| `sync_lww(key, at, device, value)` | самая свежая настройка на тред, для last-writer-wins синхронизации |
| `subs(root_id, since, last_activity, checked, auto)` | треды, на которые подписан |
| `sub_members(status_id, root_id)` | посты треда-подписки, которые уже видели |
| `unsubs(root_id)` | треды, из которых пользователь вышел (автоподписка не вернётся) |
| `activity(id, type, account, status_id, sort)` | уведомления о лайках, бустах, подписках |
| `kv(key, value)` | мелкое JSON-состояние: `initialized`, `source_since:<src>`, `activity_seen`, состояние GUI (`geometry`, `lane`, `posts_only.<lane>`, …), `replies_checked:<id>` |

* `Store.items_version[source]` и `status_version` растут при каждом изменении;
  `Core.lane_entries` использует их как ключ кэша.
* Изменения схемы: `CREATE TABLE IF NOT EXISTS` для новых таблиц; новые столбцы
  добавляются в `Store._migrate()` (см. миграцию v2 с `reply_to`). Данные не выбрасываем
  никогда.
* `prune(source, keep)` оставляет в каждом источнике `Core.keep_per_lane()` самых свежих
  элементов (`storage.keep_per_lane`, 3000; меньше, пока хранилище превышает бюджет).
* `gc(keep_activity, grace_hours, drop_read)` забывает то, на что ничто не указывает: статус
  остаётся, пока на него указывают `items`, `sub_members`/`subs`, `activity`, черновик
  `reply:`, пока он мой или сохранён в пределах `grace_hours`, и пока на него бустит,
  его цитирует или отвечает оставленный статус (обход по уровням вверх по треду, во
  временной таблице). Ещё он обрезает `activity` до `keep_activity` самых свежих,
  `sub_members` покинутых тредов, `missing`, на которые никто не отвечает, устаревшие ключи
  `replies_checked:` и — `drop_read`, только при нехватке места — отметки о прочтении
  статусов, которых больше нет. `aliases` не трогаются никогда. Потом
  `PRAGMA incremental_vacuum` (файл в `auto_vacuum=INCREMENTAL`; схема v5 один раз
  переводит старый файл через `VACUUM`) и checkpoint WAL.
* `Core.collect_garbage()` запускает его раз в `storage.gc_hours` из опроса: выше
  `storage.max_mb` он режет каждую ленту на 30 % (`next_keep`, пол `KEEP_FLOOR` = 300),
  чистит и собирает снова, пока не влезет; сильно ниже бюджета длина ленты (kv
  `storage.keep`) растёт обратно к конфигу. Каждый раз — строка `storage gc:` в журнале.

## 7. Источники и догон (`core/sources.py`)

**Источник** — поток сервера: `home`, `mentions` (уведомления типа mention), `mine` (мои
статусы), `local` и `list:<id>` для каждого списка. У Source есть
`fetch(limit, max_id, min_id)` и `entry(raw) → (item_id, status, created)`.

* `catch_up()` идёт **вперёд** от самого свежего сохранённого элемента через `min_id`,
  страница за страницей, пока страница не окажется короткой или не упрётся в
  `feed.catch_up_limit`. Так в локальной копии нет дыр и читать можно по хронологии.
* Первый раз (`_fill_empty`): одна страница. Если источник уже смотрели, но он был пуст
  (`kv source_since:<name>`), он идёт назад до того момента, чтобы не пропустить
  пришедшее за это время.
* `fetch_older()` — кнопка «Раньше»: одна страница с `max_id` самого старого элемента.
  Старая история считается прочитанной.
* `subs` — *локальный* источник (его заполняет `core/subs.py`, а не сервер);
  `lanes.LOCAL_SOURCES` держит его вне `sources_needed`.

## 8. Ленты (`core/lanes.py`)

Лента — то, что показывает боковая панель: `Lane(name, source, keep, by_status_time)`.
`keep(status, ctx)` фильтрует элементы источника; `ctx` — это `LaneContext(me_id,
extra_bots, mentions_all, subs_replies_to_me, hidden)`.

| лента | источник | что оставляет |
|---|---|---|
| `home` («Лента») | home | не ботов, не тех, кто в исключающем списке |
| `replies` («Ответы мне») | mentions | ответы на мои посты и комментарии |
| `mentions` | mentions | прочие упоминания (`lanes.mentions_all` → все) |
| `subs` («Подписки») | subs (локальный) | новые комментарии в тредах-подписках, кроме ответов мне |
| `bookmarks` | bookmarks | что ещё в закладках; *ленивая*; листается по заголовку Link (`sources._Cursor`); `core.bookmark()` сразу добавляет и убирает |
| `activity` («Активность») | — (своя таблица) | лайки, бусты, подписки (`ActivityWidget`) |
| `bots` | home | ботов, не тех, кто в исключающем списке |
| `my_posts` | mine | всё |
| `local` | local | всё; *ленивая* |
| `federated` («Федерация») | federated | всё; *ленивая* |
| `my_likes` («Мои лайки») | favourites | что ещё лайкнуто; *ленивая* |
| `requests` | — | заявки на подписку (`RequestsWidget`) |
| `list:<id>` | list:<id> | всё (по одной на каждый список сервера, после встроенных) |

* **Ленивые (листаемые) ленты** — `local`, `federated`: забираются только пока на экране
  (`core.set_active_lane`, окно зовёт его при каждом переключении), только свежая
  страница (`sources.refresh_top`; дыра там допустима), без отметок непрочитанного и
  счётчиков.
* **Разделы боковой панели** — `lanes.GROUPS` / `lanes.grouped()`: «Стандартные», от самой
  широкой вниз (federated, home, local, bots), «Личные» (my_posts, mentions, replies,
  subs, bookmarks, activity, requests), «Списки» внизу; порядок из конфига держится внутри
  раздела
  (`ui.sidebar_groups = false` → один плоский список). Строит её
  `MainWindow._rebuild_sidebar()` (заново на `lists_changed`); Alt+1…9 идут по `lane_order`,
  а не по строкам.

* **Имена** — имя встроенной ленты — слово, которое переводит её заголовок (0.15:
  `people`→`home`, `comments`→`replies`, `global`→`federated`, `mine`→`my_posts`,
  `favourites`→`my_likes`; источники хранят имена из API). `lanes.RENAMED` /
  `lanes.canonical()` понимают старые имена везде, где ленту называют: опции
  `config.LANE_LISTS`, CLI, веб-API; `Store._rename_lanes()` (схема 3) один раз переносит
  запомненную окном ленту, колонки и выборы по лентам.
* `lanes.enabled(cfg, lists)` строит список из `lanes.enabled` плюс ленты списков.
  `Core._apply_lists()` подменяет `Core.lanes`/`lane_by_name`, когда меняются списки.
* `Core.lane_entries(name)` возвращает `[(item_id, status)]` от старых к новым, не больше
  `feed.render_limit` (его поднимают «Раньше» и «Глубже» в Ctrl+F через `_limits`),
  отфильтрованные `keep` и «только посты». Кэшируется, пока хранилище не изменится.
  Ленты с `by_status_time` (уведомления) сортируются по времени самого поста.
* Участники списков уходят из общих лент: `Core._hidden_authors()` собирает участников
  всех списков (`lists.hide_members = "all"`; или только исключающих, или никого), а
  `lanes.keeps()` выбрасывает их посты и бусты из лент в `lists.hide_in`
  (по умолчанию home, bots, federated, local); их показывает лента списка.

## 9. Один опрос, по шагам (`Core._poll_once`)

1. Списки и участники перечитываются раз в `lists.refresh_minutes` (`_refresh_lists`).
2. Проверяются подписки (`subs.check`) → новые элементы в источнике `subs`.
3. Каждый нужный источник догоняется (`sources.catch_up`) и чистится. 401/403 →
   событие `auth_failed` и стоп.
4. Забираются заявки на подписку; новые (по сравнению с прошлым опросом) отмечаются.
5. Уведомления активности забираются вперёд (`_poll_activity`); самый первый раз это
   история (помечается виденной).
6. Правила прочтения: при самом первом запуске всё помечается прочитанным
   (`feed.first_run_mark_read`); мои собственные посты прочитаны всегда; пост, на который
   я ответил (из любого клиента), прочитан.
7. На мои новые посты и комментарии включается автоподписка (`subs.auto`).
8. Новые элементы раскладываются по лентам → событие `lanes_updated {lane: [item ids]}`.
9. Уведомления рабочего стола для лент из `notify.lanes` (`"all"`: все ленты) и не из
   `notify.except` (`Core._notify_wanted`; только непрочитанные) →
   событие `notify [(lane, status|account|notification)]`.
10. Родители новых ответов забираются в фоне (событие `parents`).
11. Раз в `storage.gc_hours`: `collect_garbage()` (см. §6).
12. Строка в журнале: что пришло и сколько заняло.

## 10. Прочитанное и «ничего не прыгает»

* Отметки живут в `read`. Что *увидено*, решает GUI: `FeedView._emit_seen`
  (через 350 мс после остановки прокрутки) сообщает карточки, целиком попавшие на экран
  (или высокие, которые прокрутили, или хвост в конце) → `core.mark_read`. Режимы:
  `read.mark_read = on_scroll | on_open | manual`.
* Открытая лента встаёт на первое непрочитанное (`feed.start_at`); строка-разделитель
  «новое ниже · N» закрепляется там, где читатель стоял при открытии ленты.
* Удержание позиции: `FeedView` хранит **цель** (`("anchor", key, offset)`,
  `("row", key, top|bottom)` или `("end", …)`) и применяет её заново на каждом
  `rangeChanged`, пока пользователь не прокрутит или не пройдёт 1,5 с — подписи с
  переносом строк получают настоящую высоту через несколько проходов раскладки, так что
  одноразовая прокрутка промахнулась бы.
  `set_specs()` переиспользует существующие строки и держит верхнюю карточку на месте.
* Скрытые ленты только ставят `dirty`; перестраиваются, когда их покажут.

## 11. Контекст ответа и «ты ответил»

* `core.parents_for(statuses)` → `{id: parent | "missing" | None}` за два запроса.
  Неизвестных родителей забирает `ensure_parents` (в фоне); отказы идут в `missing`.
  Карточки показывают цитату над текстом (`card._context_html`).
* `core.my_replies(statuses)` → мои ответы на каждый пост по столбцам `reply_to/author`.
  `check_my_replies` (ленты ответов и упоминаний) забирает контекст постов с ответами,
  которых мы не знаем, по разу на число ответов, так что ответы, сделанные из других
  клиентов, тоже видны как «ты ответил».

## 12. Возможности поверх этого

* **Треды** — `core.thread(id)`: статус + `/context`, сохраняются, `threads.build()`
  раскладывает их в порядок обхода в глубину с номерами `/N`; ответы, чей родитель не
  виден, висят под корнем. `ThreadWidget` встаёт на пост, откуда ты пришёл.
* **Подписки** (`core/subs.py`) — в Mastodon их нет. Тред-подписка — строка `subs`
  (id корня) + `sub_members` (посты, которые уже видели). `check()` перечитывает контекст
  тредов, которым пора (`interval_minutes`, только треды, живые в пределах `active_days`,
  `max_threads` за раунд), и кладёт в источник `subs` посты, которые не в участниках,
  новее `since` и не мои. Ручная подписка: каждый текущий пост считается «виденным».
  Автоподписка (свои посты и комментарии): новости — посты после моего. Отписка пишет
  `unsubs`, чтобы автоподписка не вернулась.
* **Списки** — списки сервера, см. §8. Создание, правка и участники идут прямо в API,
  потом `_refresh_lists()` → событие `lists_changed` → боковая панель перестраивается.
* **Активность** — `notifications?types[]=…` (`activity.types`) хранятся в `activity`;
  непрочитанное — новее `kv activity_seen`; `ActivityWidget` группирует соседние записи
  одного вида про один пост.
* **Поиск** — `core/search.py`: строка для поиска без учёта регистра и ё (текст, CW,
  alt-тексты, имя и @адрес автора, бустнувший, `#id`); каждое слово запроса должно
  встретиться. `FindBar` ищет по строкам на экране; `core.deep_find()` проходит всё
  сохранённое для ленты и поднимает её лимит показа до следующего совпадения.
* **Честные счётчики** — `protocols/mastodon/counters.py`: для публичных постов с других
  серверов GET `https://<origin>/api/v1/statuses/<id>` *без токена*, оставляем большие
  числа; раз в 10 минут на пост; по умолчанию выключено (`feed.honest_counters`).
* **Треды целиком** — `Core._thread_nodes()` читает контекст *верхнего* поста (контекст
  поста содержит только его ветку), так что тред выглядит одинаково от любого поста.
  `core/replies.py` + `Core._complete_thread()`: объект ActivityPub верхнего поста
  забирается с его сервера (без токена), коллекция `replies` обходится на несколько
  уровней вниз, и каждый адрес ответа, которого не знает мой сервер, разрешается через
  мой сервер (`/api/v2/search?resolve=true`); потом `thread_grew` заставляет открытый тред
  перезагрузиться. Раз в 5 минут на тред; `feed.complete_threads`.
* **Сохранение картинок** — `core/saving.py` (куда, имя файла, без перезаписи) +
  `Images.save()` (из кэша, когда можно).
* **Подсказка CamelCase** — `core/hashtags.flat_tags()`, показывается под текстом поста.
* **Ссылки остаются внутри** — `core/links.in_app(html, status)` переписывает href до
  `text.clean()`: известные @упоминания → `fedtail:account/<id>`, хэштеги →
  `fedtail:tag/<name>`, похожие на федиверс адреса профилей и постов (и неизвестные
  упоминания) → `fedtail:resolve/<quoted url>`. `core.resolve(url)` спрашивает сервер
  пользователя (`/api/v2/search?resolve=true`), и окно открывает тред или профиль;
  браузер — только если ничего не нашлось. Флаг `ui.links_in_app`.
* **Командная строка** — `core/commands.py` разбирает строку в `Command` (чистая
  функция, с тестами); `qt/cmdline.py: CommandBar` показывает, что сделает Enter, и
  выполняет через `core.target(alias, n)` (короткий id или комментарий /N его треда),
  `core.find_user`, `core.post/boost/bookmark/subscribe/follow`.
* **Вид «Беседами»** — `threads.conversations(entries, get_status, unread)` группирует
  записи ленты по самому верхнему известному посту их треда; `LaneWidget` строит по
  карточке на группу (`extra["conversation"]`), и увиденная карточка помечает
  прочитанными всех своих участников. Есть только над «Ответами мне», «Упоминаниями» и
  «Подписками» (`feed.CONVERSATION_LANES`); держится на время запуска через
  `core.choice()` (или в `kv` с `feed.remember_choices`), как «Всё | Посты | Новое».
* **Правка** — `core.source()` (`/statuses/:id/source`, набранный текст) →
  `Compose(edit=st)` → `core.edit()` (`PUT /statuses/:id`, id медиа передаются снова,
  чтобы остались); `core.history()` кормит `MainWindow.show_history`; карточки
  показывают «изменено», когда есть `edited_at`. Черновики правок — с ключом `edit:<id>`.
* **Тишина** — `core.mute/block` (сервер) + множества `core.muted/blocked`, обновляемые
  раз в `lists.refresh_minutes`; `core.silenced(st)` (автор или бустнувший заглушён или
  заблокирован, или фильтр сервера с действием "hide") применяется в `lane_entries` и
  `_notify`; фильтры "warn" сворачивают карточку как CW (`card._build`). Фильтры:
  `/api/v2/filters` (`core.filters/add_filter/delete_filter`), окно — `qt/silence.py`.
* **Поиск и подписка** — `core.search(q)` (`/api/v2/search?resolve=true` +
  relationships), `core.people(acc, "following"|"followers", max_id)` (листание по
  заголовку Link через `Api.get_page`), `core.follow`, `core.follow_tag`/`tag_info`/
  `followed_tags`. Qt: `SearchWidget` (поле в боковой панели, Ctrl+K), `PeopleWidget`,
  переиспользуемые `AccountRow` и `TagRow` со своими кнопками «Подписаться».
* **Содержимое поста** (`card.py`) — `_link_card` (status.card; `feed.link_cards`),
  `_emoji_label` (свои emoji: `text.emojify` направляет `<img>` на картинку, уже лежащую в
  кэше `Images`, `Images.local(url)`, и перерисовывает подпись, когда приходит
  недостающая; `feed.custom_emoji`), `_quote` (`model.quoted()` понимает Quote/ShallowQuote
  Mastodon 4.5, цитаты целым статусом Akkoma/Fedibird; состояния кроме
  "accepted" объясняются; `model.without_quote_fallback` убирает абзац «RE:»;
  `feed.quotes`), чувствительные медиа закрыты до клика (`feed.sensitive_media`),
  перевод через `ctx.translate` (`feed.translate`; карточка держит его и переключает).
* **Дополнение в редакторе** — `#` из `store.tag_counts()` + теги, на которые подписан, `@` из
  `store.people_counts()`, потом `core.search_people()` (без resolve); оба строятся лениво
  за один проход SQL (json_each) и поддерживаются в актуальном виде `put_statuses`;
  `Compose._offer`.
* **Маркеры** — `Core._sync_markers()` после каждого опроса (`read.sync_markers`): pull —
  всё до `last_read_id` другого клиента (home → источник home, notifications → источник
  mentions) помечается прочитанным по разу на новый маркер; push — самый свежий элемент,
  до которого всё старое прочитано, уходит на сервер. Id сравниваются через
  `model.id_after` (числа или ULID одинаковой длины).
* **Синхронизация между устройствами** (`core/sync/`, docs/ru/sync.md; `sync.*`, выключена,
  пока не задан `sync.url` или `sync.folder`: это отдельный сервис, его никогда не ищут сами) —
  `Sync` (engine.py) создаёт `Core.__init__`, если `engine.wanted(cfg)`; `Core.mark_read`,
  `subscribe`, `unsubscribe`, `mute_thread` пишут в `sync_out` хранилища (отметки о
  прочтении — только сделанные *пользователем*: `store.mark_read`, вызванный самим ядром,
  не записывается), состояния тредов — ещё и в `sync_lww` (ключ `t:<root>`, `(at мс,
  device)` — побеждает самое свежее). Поток `fedtail-sync` (запускает `start_polling`,
  останавливается первым в `shutdown` после последней отправки) раз в
  `sync.interval_seconds` или через 3 с после записи:
  `sync_pending` → пачки операций, запечатанные `crypto.seal` (AES-256-GCM ключом
  `data/sync.key`, id ключа открыто) → `backend.push`; потом `backend.pull(cursor)` (kv
  `sync.cursor`, сбрасывается при смене `sync.where`) → `crypto.unseal` → `Sync.apply`:
  прочитанное объединяется (`read_changed`), состояния тредов идут через `sync_newer` →
  `Core.apply_thread_state` (subs.subscribe / leave, без повторной записи). Ленты
  (`sync.lanes`): `Core.move_list` и сохранённые ленты тегов (`save_tag_group`,
  `add_tag_to_group`, `drop_tag_group`) зовут `Sync.record_setting(key)` с новым значением
  kv целиком (`list_order`, `tag_groups`; ключ `k:<name>` в `sync_lww`, побеждает самое
  свежее; `Sync._stamp` держит времена одного устройства строго растущими); `apply` кладёт
  более свежее в kv и зовёт `Core.apply_lanes_state` → `_apply_lists` (боковая панель
  перерисовывается). Плитки
  (`sync.tiles`): `Core.set_pinned_tiles` → kv `pinned_tiles`, так же; применение →
  `tiles_changed`. Черновики (`sync.drafts`): `Core.save_draft` / `delete_draft` (и при
  отправленном посте) помечают ключ изменённым; `_flush_drafts` раунда отправляет
  последнюю версию каждого без `media` (файлы этого компьютера; черновик из одних картинок
  не отправляется), `None` для удалённых (ключ `d:<ключ черновика>`, побеждает самое
  свежее); при применении локальные `media` для этого ключа остаются, → `drafts_changed`.
  Активность (`sync.activity`): `dismiss_activity` / `answer_interaction` записывают то,
  что вернул `store.activity_hide`, `(id, sort, ключ группы)`; применяется через
  `store.activity_hide_known` (объединяется в `activity_hidden` / `_groups`, строки
  уходят) → `activity_updated`. Каждый раунд
  и каждая проблема излучают `sync_changed`; `frontends/common/syncline.py` превращает
  `sync_status()` в «⇅ 21:40 / … / ! / выкл» строки состояния (Qt, GTK) и строку в
  «О программе». Бэкенды
  (backends.py): `HttpBackend` (fedtail-sync: `syncserver/fedtail_sync.py`, файл на stdlib
  вне пакета; токен из `data/sync_auth.json`, приложение с `read:accounts`, которое
  делает `fedtail sync login`; URL только из `sync.url`) и `FolderBackend` (`sync.folder`,
  по подпапке на устройство; заданы оба — ошибка конфига). Нет ключа, а в хранилище
  чужие блобы → новый ключ не делается, ошибка просит `fedtail sync join`. Проблемы
  выходят по разу событиями `error` и остаются в kv `sync.last` (`fedtail sync status`).
* **Короткие имена** — `store.aliases()`: пост со старым именем от счётчика (таблица
  `aliases`, 3–4 знака) сохраняет его; остальные получают `short_code(id)` (буква +
  base-36 от sha256, 8 знаков хранятся в `short_ids`), показываются обрезанными до
  `SHORT_LEN` = 5, длиннее, пока начало совпадает с другим известным кодом. Одинаковы на
  всех устройствах аккаунта.
* **Асинхронное обновление** — Mastodon 4.5 отвечает на `/context` с
  `Mastodon-Async-Refresh`; `Api.last_async_refresh()` читает заголовки последнего ответа
  (по потоку); `Core._await_refresh()` опрашивает `/api/v1_alpha/async_refreshes/:id` и
  излучает `thread_grew`, когда оно закончилось.
* **Чужие профили** — `Core.posts_from_origin(acc)`: актор (acc.uri или url,
  AP Accept), первые страницы его outbox (`replies.outbox_post_uris`: Create, публичные),
  каждый пост разрешается через мой сервер (`feed.remote_profiles`, `remote_posts`);
  `AccountWidget._from_origin` спрашивает, когда у моего сервера постов меньше, чем
  насчитывает профиль. `Core.people_from_origin(acc, which)`: коллекция
  followers/following актора, разрешается так же, по кнопке «ещё — с их сервера»
  (`feed.remote_people`).
* **Личные** — лента `direct` = источник mentions, видимость direct; с
  `lanes.direct_apart` такие посты уходят из ответов и упоминаний (`LaneContext.direct_apart`).
* **Дополнения к посту** — `Core.post(..., sensitive, poll, quote, scheduled_at)`: опросы
  (`Compose._build_poll`), `quoted_status_id` + `post.quote_policy`, `interaction_policy`
  GoToSocial из `post.who_can_*` (`model.interaction_policy`, отправляется только в
  GoToSocial), `scheduled_at` (ответ — ScheduledStatus; `show_scheduled`).
* **Модерация и люди** — `core.report` (`/api/v1/reports`), `core.block_domain`
  (`blocked_domains` входит в `silenced()`), `core.set_note` (relationship.note),
  закреплённые посты (`core.pinned`, `core.pin`; `AccountWidget.render` ставит их первыми).
* **Клавиши** — `FeedView.keyPressEvent`: j/k двигают `cursor_key` (свойство карточки
  `keyed`), r/f/b/m/o действуют через `ctx.on_link` (`ui.post_keys`).
* **Профили и теги** — `AccountWidget` (карточка: описание, поля, счётчики, «с какого
  времени», «подписан на тебя», Подписаться/Упомянуть/В список/браузер;
  `core.relationship/follow`) и `TagWidget` (`core.tag_timeline`) делят `_PagedTab`
  (лента сервера, читаемая по страницам). Клик по имени человека, чья вкладка открыта,
  прокручивает обратно к его карточке.

## 13. События (ядро → фронтенд)

Излучаются через `Core.emit(name, payload)` из любого потока; Bridge Qt переизлучает их в
GUI-потоке; разбирает `MainWindow.on_event`.

| событие | данные | когда | что делает GUI |
|---|---|---|---|
| `ready` | me | подключились | — (всю работу делает обработчик фьючерса connect) |
| `lanes_updated` | {lane: [item ids]} | новые элементы, догружено старое, состав списков | обновить эти ленты, счётчики |
| `parents` | — | забраны родители или «мои ответы» | обновить ленты и вкладки профилей |
| `read_changed` | [status ids] | добавлены отметки | снять подсветку карточек, счётчики |
| `status_updated` | status | лайк/буст/честные счётчики | строки перечитываются из хранилища |
| `status_deleted` | id | мой пост удалён | строки убираются |
| `requests_updated` | [accounts] | каждый опрос | лента заявок, счётчик |
| `activity_updated` / `activity_seen` | число / ключ сортировки | новая активность / увидена | лента активности, счётчик |
| `lists_changed` | [lists] | изменились списки или участники | блок списков в боковой панели перестраивается |
| `subs_changed` | id корня | подписка/отписка | кнопки в шапке треда |
| `me_updated` | me | профиль сохранён | имя и аватар в боковой панели, вкладка моего профиля |
| `notify` | [(lane, obj)] | после опроса | `Notifier` (уведомления рабочего стола) |
| `error` | текст | исправимый сбой | строка состояния (и журнал) |
| `unsupported` | имя возможности | сервер ответил на неё 404 | её пункты меню и кнопки прячутся |
| `auth_failed` | текст | 401/403 | окно повторного входа |
| `arrived` | [(post id, reply-to id)] | сохранены новые посты | вкладки тредов растут, лица |
| `thread_grew` | id корня | в треде-подписке появились ответы | его вкладка перезагружается |
| `rate_limited` | {until, left, …} | бюджет запросов сервера на исходе | одна строка состояния |
| `first_poll_done` | None | первый круг опроса закончен | «получаю ленты…» уходит из строки состояния |
| `capabilities_changed` | возможность | сервер ответил «такого нет» | кнопки сразу прячутся |
| `prefetch` / `prefetch_video` | [urls] | после опроса | картинки и видео забираются заранее |
| `sound` | имя события | новости (core/sounds.py), подключение, пост отправлен | звук темы (common/sound.py) |
| `sync_changed` | None | раунд синхронизации закончен или встретилась проблема | слово «⇅» в строке состояния (common/syncline.py) |
| `drafts_changed` | [ключи черновиков] | другое устройство изменило черновики (sync) | — (окно написания, открытое позже, читает новое) |
| `tiles_changed` | [имена лент] | другое устройство закрепило другие плитки (sync) | обзор лент на телефоне |

## 14. Фронтенд на Qt

* **Справка и «Что это?»** — ≡ → Справка (`MainWindow.open_help(page, anchor)`) показывает
  `HelpPanel`, одну на окно; её прячут, а не уничтожают, чтобы она возвращалась туда, где
  её оставили. ≡ → Что это? переключает `MainWindow.hints` (`HintMode`; `ui.whats_this`
  включает при запуске): пока включено, фильтр событий на QApplication отвечает на каждый
  `QEvent.ToolTip`, чей текст — строка i18n со строкой в `data/help/<lang>/hints.toml`, —
  так что новая кнопка получает подсказку одной строкой, без кода.
  Клавиш нет ни у той, ни у другой: F1 / Shift+F1 рядом с Esc (тест проверяет, что F1 не занят).
* **`ViewContext`** (window.py) — то, что карточке нужно от окна: cfg, тема, картинки,
  `on_link`, `open_url`, `show_images`, `me_id`, `subscribed`, `fill_list_menu`,
  `save_image`. Карточки никогда не импортируют окно.
* **Ссылки внутри приложения** — `fedtail:<action>/<arg>` (`text.link()`), их разбирает
  `MainWindow.on_link`: `thread`, `account`, `tag`, `resolve`, `reply`, `fav`,
  `boost`, `open`, `delete`, `sub`, `unsub`. Подписи красят ссылки прямо в тексте (QLabel игнорирует QSS для `<a>`).
* **`CardSpec`** (card.py) описывает одну строку: статус, глубина, номер `/N`, родитель,
  непрочитанность, фокус, in_thread, extra (my_replies, short_id, separator). `PostRow`
  перестраивается, только если спецификация правда изменилась (`update_spec`).
* **`FeedView`** (feed.py) — QScrollArea с колонкой строк по центру (`ui.max_width`),
  логика цели из §10 и сигнал «увидено».
* **`LaneWidget`** = шапка (заголовок, «N новых», переключатель «только посты», «К новому»,
  «Всё прочитано», обновить) + FeedView + кнопка «Раньше». `refresh()` строит спецификации
  из `lane_entries`, родителей, моих ответов, коротких id и разделителя.
* **`MainWindow`**: боковая панель (аккаунт, «Написать», `QListWidget#lanes` из `LaneItem`,
  блок списков, подвал), `QTabWidget`, чья первая вкладка — `QStackedWidget` из виджетов
  лент, а остальные — треды и профили, строка поиска, трей, сочетания клавиш. Esc
  закрывает то, что сверху; последний Esc показывает *шторку* (`right_stack` страница 1: ни одной ленты на экране, так что ничего не помечается прочитанным; `ui.esc`).
* **Написание**: черновики сохраняются по ходу набора (`post.drafts_autosave`); все выходы
  идут через `reject()` → `_leave()`; никогда не зови `close()` внутри `reject()`
  (closeEvent Qt зовёт reject → бесконечный цикл). Ядро само удаляет черновик после
  успешного поста (`draft_key`), даже если окна уже нет.
* **Картинки**: `get(url, callback, max_side, failed)`; кэш QPixmap в памяти
  (LRU с ограничением в байтах, `ui.image_cache_mb`) + кэш на диске (`cache/` по sha1 от URL; хранятся только декодируемые файлы);
  лента просит 1200 px, просмотрщик — полный размер.
* **Уведомления**: `notify.Notifier` → `notify-send --action=open --wait` в отдельном
  потоке (чтобы «Открыть» могло вывести окно к треду), иначе всплывашка трея;
  молчит, пока окно активно, если не `notify.when_focused`.

## 14b. Общие решения и фронтенд на GTK

Рисуют оба окна; что делает ссылка, какие действия есть у поста, как устроено письмо и что
делает командная строка, решается один раз в `frontends/common/` (без тулкита, проверяет
тест в `test_layering.py`). Окно отдаёт каждую ссылку `fedtail:` в
`Links(view, host).open(url)`; хост отвечает на `call` (мост), `status`, `error`,
`confirm(title, text, then)` — then() только при «да», и оно может прийти позже (диалоги
GTK не блокируют) — `compose(reply_to, invite, edit, quote)` и места `open_*`. Хост, у
которого места ещё нет (GTK: жалоба, цитаты…), получает статус «здесь пока нет». Хост Qt —
`_LinkHost` в window.py, хост GTK — его `MainWindow`.

Фронтенд на GTK (`frontends/gtk/`, план и этапы — в docs/ru/dev/gtk.md):

* `__init__.py` run(): libadwaita, если позволяет `ui.adwaita`, `Gtk.Application`
  NON_UNIQUE (у fedtail свой сокет экземпляра), app id `version.APP_ID`.
* `bridge.py` — фьючерсы и события в главный цикл GLib (`GLib.idle_add`), данные событий
  уже модель (`View.event_payload`).
* `lane.py` — лента строит только окно карточек (`WINDOW` вокруг места, откуда начинается
  чтение), пачками по `BATCH_MS` между кадрами, `STEP` ещё у края, обрезается после
  `MAX_ROWS`; строки, вставляемые выше видимой области, держат её на месте (`_hold`:
  изменения высоты в том же кадре, верхний пост возвращается на место на каждом тике
  кадра). `seen()` решает, что «прочитано».
* `card.py` — карточка из модели и `common/actions.py`; `images.py` — текстуры из
  `View.media_bytes`, LRU с ограничением в байтах; `compose.py`, `cmdline.py` — редактор
  и командная строка поверх `common/compose.py` и `common/commands.py`.
* `theme.py` — CSS из файлов тем через `palette.py`; цвета "auto" — от Adwaita
  (у GTK 4 нет палитры рабочего стола), акцент — из libadwaita ≥ 1.6.
* Вне GNOME окно сохраняет рамку рабочего стола (`ui.gtk_headerbar`): зависшая
  клиентская шапка может держать указатель, как было в KDE.

## 15. Темы

* Файлы: `fedtail/data/themes/*.toml` (встроенные) и
  `~/.config/fedtail/themes/*.toml` (пользователя, сильнее встроенных). Тема может
  `inherit` другую. `system.toml` — эталон: каждый ключ с комментарием.
  `themefile.load()` разрешает наследование и проверяет (без Qt).
* Секции: `[font]` (список семейств, mono, post_scale), `[colors]` (hex или "auto" =
  выводится из палитры рабочего стола), `[shape]` (радиус, вид карточки card|rule,
  аватары, иконки, шапка rich|compact, метка непрочитанного, переключатель «только
  посты»), `[words]` (шаблоны вроде `lane_title = "== {text} =="`, формат даты, нижний
  регистр), `[icon]` (стиль bubble|terminal и цвета; "auto" = от акцента — фронтенд
  рисует иконку через `iconart.svg()` в папку кэша при запуске).
* `qt/theme.py`: `Theme` разрешает цвета (`_auto_colors`, `_readable_on`),
  `stylesheet()` генерирует весь QSS, `apply()` ставит палитру, шрифты (только
  установленные семейства — отсутствующее может быть подменено с абсурдными метриками) и
  таблицу стилей.

## 16. Конфиг

* `core/config.py: DEFAULTS` — единственный источник правды: секция → ключ →
  значение по умолчанию. `validate()` строго проверяет типы (bool — не int), `CHOICES`,
  `MINIMUM`, имена лент; неизвестные ключи — предупреждения, неверные значения — ошибки.
* `fedtail/data/config.example.ru.toml` описывает каждую опцию по-русски, по главам
  (баннер перед каждой секцией, подзаголовки внутри `[ui]`; блок комментариев, за которым
  пустая строка, не принадлежит ни одной опции), каждая опция стоит в значении по
  умолчанию; тест проверяет, что разбор файла даёт ровно `DEFAULTS`.
  `config.example.en.toml` — его английский близнец: каждая строка, которая не
  `# комментарий` (секции, опции, закомментированные опции, баннеры глав), та же и в том
  же порядке — тест их сравнивает. Новый конфиг пишется на языке рабочего стола
  (`config.default_language()`).
* `config_update.py`: находит опции, которых нет в файле пользователя, и вставляет их с
  пояснениями (`--update-config`); `rebuild()` раскладывает файл пользователя заново по
  примеру, подставив его значения (`--rebuild-config`).

## 17. Строки (i18n)

`i18n._("key", **kw)`; словари `ru` и `en` в `i18n.py`; значение-список — формы
множественного числа, выбираемые по `n` (в русском их три). Тест проверяет, что у обоих
языков одни и те же ключи. Комментарии в коде — по-английски; документы для разработчиков —
на двух языках; интерфейс по умолчанию на языке системы.

## 18. Диагностика

Сторону пользователя см. в `docs/ru/dev/debugging.md`. В коде: `fedtail/diag.py` настраивает
журнал (`SessionLog`: файл на каждый запуск и каждый час в `debug.log_dir/<profile>/`,
`latest.log` указывает на текущий, ограничение `debug.keep_mb`), `crash.log` (faulthandler),
`stacks.log` (SIGUSR1, меню, сторож), перехватчики исключений для всех потоков, поток
статистики с поставщиками (`diag.add_stats(name, fn)`: ядро добавляет счёт хранилища, пулов,
кэшей, фронтенд Qt — виджетов и картинок) и `bug_report()`. `qt/diagnostics.py`
направляет сообщения Qt в журнал и ведёт `Watchdog` от секундного таймера.
`api.py` пишет в журнал каждый запрос (метод, путь, параметры листания, статус, время,
размер — никогда токен или тела). В новых модулях — `logging.getLogger(__name__)`.

**Наблюдение за утечками** (`fedtail/leaks.py`, без Qt). Поток статистики раз в
`debug.stats_minutes` зовёт `diag.check_now()`: `log_stats()` (строка `stats`, теперь с
`gc.*`), потом `trend()` — `leaks.Trend` держит окно из `debug.leak_samples` значений на
каждую наблюдаемую метрику (`leaks.WATCH`: имя → рост за окно, который ещё шум), пишет
сводку `trend` (с начала → сейчас, скорость в час по наименьшим квадратам) и предупреждение
`possible leak`, когда метрика росла на каждом замере окна больше своего порога шума (не в
первые 30 мин; снова — когда рост с начала удваивается). Строки хранилища
(`leaks.SUMMARY_ONLY`) растут нарочно и только сводятся. В режиме отладки
(`debug.object_census`) `leaks.python_objects()` (обход `gc.get_objects()` по типам,
несколько сотен мс) идёт через `diag.census("python", …)` — `leaks.Census`, который
сравнивает с прошлым и первым счётом. Виджеты Qt трогаются **только** в GUI-потоке:
`qt/diagnostics.py` считает их по 30-секундному таймеру окна в словарь, копию которого
возвращает поставщик статистики `qt`, и кормит `census("qt_widgets", …)` по классам
на каждом интервале статистики. tracemalloc: `leaks.start_tracing()` / `stop_tracing()` /
`snapshot(folder)` пишет `memory-<time>.txt` (верхние строки по размеру, рост с первого
снимка, трасса самого растущего); `debug.tracemalloc` включает его при запуске, меню
«Отладка» переключает. `diag.session_summary()` — последняя строка перед `session end`.
Чтобы наблюдать новое число: верни его из поставщика статистики и добавь имя и порог шума
в `leaks.WATCH`.

## 19. Тесты и CI

* `python3 -m unittest discover -s tests -t .` — без сети и без дисплея.
  Тесты Qt пропускаются без PySide6; CI гоняет их offscreen.
* `tests/fakes.py`: `FakeApi` + `World` — сервер в памяти (ленты, уведомления, статусы с
  контекстом, списки, активность, профиль). `World.add()`, `World.act()`; `FakeApi.world`
  общий для всех экземпляров, которые создаёт ядро.
* `test_core.py` — догон, ленты, уведомления, подписки, списки, активность,
  глубокий поиск, честные счётчики, черновики, миграция хранилища.
  `test_qt_smoke.py` — одна длинная прогулка по окну (открыть ленты, написать,
  треды, поиск, Esc, профиль, списки, активность, картинки, диагностика).
  Остальные: конфиг/CLI, темы, текст уведомлений, поиск, чистка текста, сохранение,
  диагностика. `test_leaks.py` — вердикты трендов с поддельными часами, перепись, снимки
  tracemalloc, цикл статистики. `test_resources.py` — «ночь за секунды»: 70 опросов и
  1000+ постов через ядро с маленьким лимитом чистки; строки хранилища, кэши, очереди,
  словари «в пути», потоки и объекты Python должны оставаться ограниченными, а опросы
  быстрыми (фейковый сервер забывает старые посты, так что меряется именно fedtail).
  Прогулка по Qt проверяет, что закрытые вкладки тредов и профилей не оставляют виджетов.
* CI (`.github/workflows/ci.yml`): ruff; тесты на Python 3.11–3.13 с PySide6 из pip;
  тесты на Debian 13 с Qt из apt (настоящая цель; там нет QtTest); вручную
  (`workflow_dispatch`, только main) `tools/screenshots.py` рисует каждую тему с
  выдуманными данными и принудительно пушит PNG в ветку `screenshots` — картинки README;
  никогда на пуш. Галерея сайта (`tools/gallery.py`) делается только по просьбе:
  `selfcheck.py --only gallery`. `.github/annotate.py` превращает падения в аннотации
  (журналы задач не всегда можно скачать).
* Линтер: `ruff check .` (длина строки 100).
* Доки: `python3 tools/docs_build.py` пишет все генерируемые документы, `--check`
  (его запускает тест) падает, если какой-то устарел. Исходники: `docs/src/features/*.toml`
  (каждая возможность со статусом, `since`, ключом конфига, API, другими клиентами, текстами
  на `ru` и `en` — простая строка одна на оба языка) → `docs/<lang>/features.md`,
  `comparison.md` и части `features-short`, `only-in-fedtail`, `whats-new`,
  `roadmap`; два примера конфига → `docs/<lang>/config.md`. Написанные руками части лежат
  в `docs/<lang>/parts/`. Любой README, страница `docs/` или справки вставляет часть через
  `<!-- include: parts/NAME -->…<!-- /include -->` (`shift=N` понижает её заголовки,
  `lang=xx` — где путь не говорит языка); текст между маркерами переписывает сборка, так
  что файл на GitHub читается целиком. Ссылки в частях идут от корня репозитория
  (`/docs/en/features.md`). Части не вставляют части.

## 21. Соглашения и ловушки

* Публичный репозиторий никогда не называет собственный сервер автора; никакой сервер не
  зашит в код.
* Токен живёт только в `auth.json` (0600) и в заголовке `Authorization`;
  ничто его не пишет в журнал; отчёты об ошибках не включают его и базу.
* Запросы к серверам кроме сервера пользователя (картинки, честные счётчики) никогда не
  несут токен.
* `Compose.reject()` не должен звать `close()`.
* В PySide6 из Debian нет QtTest: тесты шлют события клавиш через `QApplication.sendEvent`.
* Qt удаляет виджеты у тебя из-под ног: защищай обработчики (`RuntimeError … already deleted`).
* Вспомогательная функция теста, вставленная между декоратором и его классом, молча
  отрывает декоратор — держи `@unittest.skipUnless(HAVE_QT…)` прямо над классом.
* Сообщения коммитов: что изменилось и почему; по-английски. Комментарии: по-английски.
  Документы для разработчиков — на двух языках, `docs/ru/dev/` и `docs/en/dev/`, правятся
  вместе.
