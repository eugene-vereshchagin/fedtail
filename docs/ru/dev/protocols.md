# fedtail: протоколы и нормализованная модель

Статус: **согласовано 20 окт 2026**. Этапы 0–4 сделаны (0.17.0); остальные — по очереди;
по мере готовности устройство переезжает в architecture.md.

## Зачем

Сейчас fedtail знает ровно один протокол — Mastodon API, и знает его везде:

| где | как прибито |
|---|---|
| `core/api.py` | REST-клиент Mastodon — это нормально, транспорт изолирован |
| `core/store.py` | в базе лежит сырой JSON сервера (`statuses.data`) |
| ядро (`threads`, `stream`, `counters`, `app`, `health`) | прямые пути `/api/v1…`, поля `reblog`, `in_reply_to_id` |
| фронтенды (13 файлов, ~77 мест) | читают поля Mastodon напрямую: `account`, `spoiler_text`, `reblog`… |
| порядок | `id_after()` и `sort_key()` полагаются на то, что id — snowflake или ULID |

Цель: Mastodon-совместимые сервера становятся **первым протоколом**, а не устройством
программы. Второй протокол (Misskey/Sharkey, Lemmy, Bluesky) добавляется
новым модулем, без правки фронтендов. Заодно на нормализованной модели строится
ростер для QIP-раскладки.

Чего **не** делаем сейчас: не пишем второй протокол. Только убираем Mastodon из всего,
что не адаптер.

**Мерило — словарь ActivityPub**, а не форма JSON Мастодона: `Note` — пост,
`Announce` — буст, `Like`, `Follow`, `Question` — опрос, `Article` — длинный пост,
`Group` — сообщество (Lemmy). Клиентский API любого сервера этой семьи ложится на
модель адаптером. Matrix, комнаты и E2EE не проектируем.

## Три слоя

```
фронтенды (qt, gtk, tui, web, cli, потом flet)
      │   видят только fedtail.model: Post, Account, Thread, Activity…
      ▼
ядро (Core: ленты, прочитанное, подписки на треды, черновики, короткие id, ростер)
      │   зовёт только интерфейс Protocol
      ▼
протоколы: protocols/mastodon (api.py + адаптер)   [потом: misskey, lemmy, bluesky]
```

Правило, как сейчас «ядро не импортирует Qt»: **вне `protocols/` нет ни одного поля
протокола**. Это проверяет тест (grep по `"reblog"`, `"spoiler_text"`, `/api/v1` и т. п.
вне `protocols/`). Сырых данных фронтенды не видят вообще: обмен идёт только по
шине модели, отладочный «показать JSON» берёт данные через ядро.

## Нормализованная модель (`fedtail/model/`)

Датаклассы, неизменяемые; изменение счётчиков — новый объект через `replace()`.

| тип | главные поля | Mastodon API | ActivityPub |
|---|---|---|---|
| `Ref` | `proto`, `profile`, `native_id` | id статуса | `id` объекта (URI) |
| `Account` | `ref`, `handle`, `name`, `avatar`, `bot`, `locked`, `fields`, `url` | account | `Person` / `Service` (бот) / `Group` |
| `Post` | `ref`, `author`, `created`, `text` (HTML-подмножество), `plain`, `warning` (CW), `visibility`, `reply_to`, `thread_root`, `media`, `poll`, `quote`, `counts`, `my` (fav/boost/bookmark), `lang`, `url`, `edited` | status | `Note` / `Article` / `Page` |
| `Share` | `by`, `post`, `created`, `sort` | boost (`reblog`) | `Announce` |
| `Media` | `kind`, `url`, `preview`, `alt`, `size` | attachment | `Image` / `Video` / `Document` |
| `Poll` | `options`, `multiple`, `expires`, `voted` | poll | `Question` |
| `Activity` | `kind` (fav/share/follow/mention/…), `who`, `post`, `when` | notification | `Like` / `Announce` / `Follow` / `Create` с упоминанием |
| `Conversation` | `ref`, `title`, `kind` (лента/тред/список/тег/сообщество), `unread` | — | `OrderedCollection` / `Group` |
| `Capabilities` | набор флагов, см. ниже | по версии сервера и 404 | по протоколу |

Текст: общий язык — **санитизированное HTML-подмножество** (то, что уже понимает
`richtext.py`). Mastodon и ActivityPub отдают HTML, MFM Misskey и фасеты Bluesky
переводятся в HTML адаптером. Фронтенды парсят один формат.

### Порядок и id

`native_id` для ядра непрозрачен. Порядок даёт **протокол**: у `Post` есть `sort`
(строка, сравнимая как текст). Для Mastodon это нынешний `sort_key(created_at, id)`. `id_after()` уходит в адаптер Mastodon.

Короткие id Point-стиля (`#a3f`) остаются в ядре и выдаются на `Ref` — им всё равно,
какой протокол.

## Возможности протокола (`Capabilities`)

Зародыш уже есть: событие `unsupported`, когда сервер отвечает 404. Делаем из этого
явный набор, который протокол объявляет при подключении и уточняет по ходу.

| флаг | Mastodon/GTS | Misskey | Lemmy | Bluesky |
|---|---|---|---|---|
| `share` (буст) | да | да | нет | да |
| `quote` | зависит от сервера | да | нет | да |
| `warning` (CW) | да | да | NSFW-метка | метки |
| `visibility` | 4 уровня | 4+ | только публично | только публично |
| `edit` | да | да | да | нет |
| `poll` | да | да | нет | нет |
| `lists`, `filters`, `followed_tags` | да | частично | сообщества | фиды |
| `threads_tree` | да | да | да | да |
| `markdown_input` | GTS/Akkoma/Pleroma | MFM | да | нет |

Фронтенд прячет кнопки и пункты меню по флагам — так же, как сейчас по `unsupported`.
Это ложится на принцип «каждая фича выключаема».

## Интерфейс протокола (`protocols/base.py`)

Обязательная часть и необязательные расширения (не умеет — не объявляет).

| группа | методы | обязательно |
|---|---|---|
| вход | `login_start`, `login_finish`, `logout`, `me` | да |
| источники | `sources()` → какие ленты есть; `page(source, before/after)` | да |
| треды | `thread(ref)` → предки + потомки | да |
| пост | `get`, `send(draft)`, `delete` | да |
| реакции | `favourite`, `share`, `bookmark`, `vote` | по флагам |
| люди | `account`, `relationship`, `follow`, `mute`, `block`, `followers/following` | да (кроме блоков) |
| уведомления | `activity(page)`, `mark_seen` | да |
| поток | `stream()` → генератор событий протокола | нет (тогда опрос) |
| поиск | `search(q, kind)` | нет |
| расширения | `lists`, `filters`, `tags`, `announcements`, `translate`, `scheduled`, `report`, `markers` | нет |

Протокол — **синхронный**, как сейчас `api.py`: ядро само гоняет его в рабочих потоках.
Это сохраняет нынешнюю модель потоков без async-переделки.

## База (`state.db`): скорость и рост

**Решено:** храним сырые данные протокола + колонку `proto`, нормализуем при чтении.

Скорость: JSON и сейчас разбирается при каждом чтении; сборка датакласса поверх —
микросекунды на пост, в окне сотни постов. Плюс кэш нормализованных объектов по
`status_version`, как кэш лент. Медленнее не станет.

**Рост — реальная проблема уже сейчас, независимо от переделки.** `prune()` чистит
только `items` (3000 на ленту) и `first_seen`, а таблица `statuses` не чистится
никогда: каждый пост, увиденный в ленте, треде или профиле, лежит вечно. Так же растут
`read`, `activity`, `sub_members`. За год активной ленты это сотни мегабайт — гигабайты.

Чинится сборкой мусора (этап 0, до переделки):

| что | правило |
|---|---|
| `statuses` | удалять посты, на которые никто не ссылается: ни `items`, ни `sub_members`, ни `activity`, ни черновик-ответ, ни открытый тред; удалённый пост при надобности перекачивается с сервера |
| `read` | отметки для постов, которых больше нет в базе и которые старше N дней |
| `activity` | держать последние M уведомлений, как ленты |
| `sub_members` | у отписанных и заглохших тредов |
| `aliases` | не трогаем: короткие id стабильны навсегда, строки крошечные |
| файл | `auto_vacuum = INCREMENTAL` и `incremental_vacuum` после чистки, чтобы файл реально худел |

Сколько хранить — флагами в конфиге, по умолчанию разумно, как всё остальное.

## Мультиаккаунт и смешанные протоколы

Уже есть: один профиль — один аккаунт, `ui.merge` собирает несколько `Core` в одно окно
(`core/merged.py`). Это и есть путь для разных протоколов: **один `Core` = один аккаунт =
один протокол**, окно смешивает. `Ref` несёт `profile`, поэтому объекты разных аккаунтов
не путаются. Ничего нового придумывать не надо.

## Ростер для QIP-раскладки (поверх модели)

`View.roster()` → `[RosterGroup]` из `RosterItem`: ленты, списки, подписанные треды,
личные беседы, взаимные («Люди», `Core.refresh_mutuals` раз в сутки); позже сообщества
Lemmy. Раскладки (`ui.layout = single | columns | split`) — забота фронтенда; ростер —
данные модели, одинаковые для всех.

## План работ (пачками, пуш в конце каждой)

| этап | что | как проверяем |
|---|---|---|
| 0 ✓ | сборка мусора в базе + incremental vacuum | тест: база не растёт на прогоне тысяч постов |
| 1 ✓ | `fedtail/model/` + адаптер Mastodon → модель; никто ещё не пользуется | тесты адаптера на `tests/fakes.py` и образцах GTS/Mastodon/Akkoma; `tools/model_check.py` — прогон адаптера по своей базе |
| 2 ✓ | ядро отдаёт фронтендам модель (`core/view.py`: View поверх Core); фронтенды по одному: cli ✓ → tui ✓ → web ✓ (переписан) → qt ✓ | `tests/test_layering.py`: во всём `frontends/` нет полей протокола и базы |
| 3 ✓ | `api.py`, поток, честные счётчики и проверка возможностей уехали в `protocols/mastodon/`; ядро берёт клиента, его ошибки, поток и `Capabilities` из `Protocol` (`protocols/base.py`), а методы клиента, которые оно зовёт, перечислены там же (`CLIENT`) | `tests/test_protocols.py`: путей `/api/v…` в коде вне `protocols/` нет, ядро зовёт только `CLIENT`, у Mastodon-клиента есть весь `CLIENT`, фронтенды не лезут в `protocols.mastodon` |
| 4 ✓ | `Capabilities` (`protocols/base.py`) — одно место: что сервер сказал о себе, ответы проверки, отказы «такого нет» и известное о софте (`KNOWN`); `Core.supports` спрашивает его, ответы переживают переподключение, последняя проверка действует с запуска; событие `capabilities_changed` — фронтенды прячут кнопки сразу | `tests/test_protocols.py`, `test_social.py`, smoke: «Очистить» уходит, как только сервер отказал |
| 5 ✓ | ростер (`View.roster()` → `RosterGroup` / `RosterItem`) и `ui.layout = "split"` на Qt: окно-ростер, окно сообщений со своими вкладками, строка ввода, лица — [layouts.md](layouts.md) | `tests/test_roster.py`, smoke + скриншоты `tools/screenshots.py` |
| 6 ✓ | темы в духе QIP, Psi+ и Агента; тема задаёт и вид раскладки (`shape.faces`, `roster_rows`, `tab_rows`, `icons`) | `tests/test_themes.py`, `test_icons.py`, скриншоты |

Этапы 0–4 пользователь не должен заметить вообще: поведение то же, CHANGELOG пишет
«внутренняя переделка». Каждый этап отдельно выпускается как dev-сборка, ты гоняешь
с подробными логами.

## Решения

| вопрос | решение |
|---|---|
| хранение | сырой JSON + `proto`, нормализация при чтении; рост лечим сборкой мусора |
| сырые данные во фронтендах | нет, только шина модели |
| название слоя | `protocols/` |
| мерило | словарь ActivityPub; Matrix не проектируем |
