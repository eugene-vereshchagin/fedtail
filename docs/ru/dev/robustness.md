# Надёжность: вопросы и ответы

Что fedtail делает в неудобных ситуациях: сеть, ОС, диск, интерфейс, безопасность,
состояние, установка, ресурсы. В каждой строке — как есть сейчас и что решено. «Сделано
в 0.20» значит, что поведение добавлено этой версией; проверки лежат в
`tests/test_robust.py` и рядом. «Решать автору» — выбор, который меняет продукт, а не
только код.

## 1. Сеть и API

| вопрос | ответ | решение |
|---|---|---|
| Таймаут соединения | `requests` с `timeout=30` на каждый запрос: и на соединение, и на каждое чтение. Опрос, упавший по таймауту, пишет строку в лог и ждёт следующего круга | есть |
| Сервер принял запрос и молчит | то же: 30 с на чтение; отправка поста — 90 с (`post.send_timeout`). Повтор отправки идёт с тем же `Idempotency-Key`, так что пост не задвоится | есть |
| Обрыв TCP посреди ответа | `requests` бросает `ConnectionError`/`ChunkedEncodingError`; круг опроса считается неудачным, данные не портятся: в базу пишется только разобранный ответ, одной транзакцией | есть |
| Повторы упавших запросов | не повторяются внутри круга; повтором служит следующий круг. Отправка поста — один повтор с тем же ключом | есть |
| Экспоненциальная задержка | круги, упавшие подряд, ждут всё дольше: 90 с, 3, 6, 12 мин, не дольше 15 мин; «Обновить» спрашивает сразу. Живой поток переподключается через 5, 15, 30, 60, 120, 300 с | сделано в 0.20 |
| Смена IP на лету (Wi-Fi → мобильный, VPN) | старое соединение рвётся; следующий круг открывает новое. Живой поток замечает тишину по пингу (60 с) и переподключается. Ничего не теряется: опрос догоняет с последнего известного id | есть |
| Сеть есть, интернета нет (Captive Portal) | ответ, который не JSON (страница входа в сеть, заглушка провайдера), — ошибка со словами «не ответ API — страница входа в сеть или прокси?»; в лог — тип содержимого и размер | сделано в 0.20 |
| HTTP 429 | запросы прекращаются до конца окна сервера (`X-RateLimit-Reset`, `Retry-After`); круги заранее притормаживают, когда бюджет почти исчерпан, с запасом на ручные действия | есть |
| Невалидный JSON | см. Captive Portal: ошибка с объяснением, без падения | сделано в 0.20 |
| Ответ 1 ГБ вместо 10 КБ | больше 32 МБ не читается: отказ по `Content-Length`, а без него — на 32-м мегабайте; соединение закрывается. Кадр живого потока — не больше 16 МБ | сделано в 0.20 |
| Проверка SSL, MITM | `requests` проверяет сертификат и имя всегда; самоподписанный не пройдёт. Токен уходит только на свой сервер по https; поток — только wss на тот же сайт. Свой корпоративный CA — переменная `REQUESTS_CA_BUNDLE` | есть |
| WebSocket: обрыв | поток только будит опрос, сам ничего не приносит, поэтому сообщения при обрыве не теряются: их принесёт опрос | есть |
| Прокси с NTLM/Kerberos | `HTTP(S)_PROXY` из окружения работают; NTLM/Kerberos — нет. Обход: локальный прокси-переходник (cntlm, px) | решать автору |

## 2. ОС и жизненный цикл

| вопрос | ответ | решение |
|---|---|---|
| Сон и пробуждение | ожидание следующего круга замечает, что компьютер спал (стенные часы ушли вперёд, монотонные стояли), и опрашивает сразу; поток переподключается сам | сделано в 0.20 |
| Смена времени или пояса | интервалы меряются монотонными часами; даты постов приходят в UTC и показываются в текущем поясе при отрисовке. Если часы врут сильно, сломается проверка TLS — это скажет ошибка соединения | есть |
| Несколько копий | одно окно на профиль; разные профили работают одновременно. Вторая копия того же профиля поднимает первую и выходит | есть |
| Как устроен Single Instance; первая копия зависла | unix-сокет в папке профиля (права 0600) или именованный канал Windows с ключом из папки профиля. Зависшую первую вторая не заменит: поток приёма отвечает, а окно не появится. Лечится завершением процесса | решать автору |
| `kill -9` / «Снять задачу» | lock-файлов нет; устаревший сокет удаляется при следующем старте, канал Windows исчезает вместе с процессом. SQLite в режиме WAL восстанавливается сам; запись конфига и логина атомарная | есть |
| Быстрое переключение пользователей | всё лежит в домашней папке пользователя (`%APPDATA%`, `~/.local/share`); у каждого пользователя свой канал и ключ, чужой процесс до окна не достучится | есть |
| Кириллица, пробелы в путях | пути — `pathlib`, вызовы без shell; есть тесты на Windows-пути | есть |
| SIGTERM, выключение | Qt и GTK по SIGTERM выходят так же, как из меню: сохраняют место окна, черновики и отметки о прочитанном; веб — тоже | сделано в 0.20 |
| Права администратора | не нужны: установщик Windows ставит в папку пользователя, deb ставится обычным путём, данные — в домашней папке | есть |

## 3. Файлы и данные

| вопрос | ответ | решение |
|---|---|---|
| Кончилось место во время записи | конфиг и логин пишутся во временный файл и подменяются за один шаг, старые остаются целы; база — транзакцией SQLite, круг опроса падает с ошибкой и ждёт дольше | есть |
| Атомарная запись | да: `config_edit.save` (с `.bak` и fsync), `auth.save`, `--update-config`, `--rebuild-config`, файлы синхронизации | сделано в 0.20 (`--update-config`) |
| Конфиг с синтаксической ошибкой | из терминала — сообщение с местом ошибки и выход; из меню или ярлыка — окно: «Запустить с настройками по умолчанию», «Открыть файл», «Выйти». Файл не трогается | сделано в 0.20 |
| Папку логов или кэша сделали только для чтения | логи уходят во временную папку (а если и там нельзя — только в терминал), запуск не падает; картинки показываются из памяти | сделано в 0.20 |
| Блокировка базы | SQLite держит свои блокировки; `busy_timeout` 5 с; два процесса на одной базе не бывают (одна копия на профиль, веб отказывается открыть занятый профиль) | есть |
| Очистка кэша, лимиты | база: `storage.max_mb` (1 ГБ), `keep_per_lane`, чистка раз в `gc_hours`; картинки на диске — `ui.image_disk_mb` (1 ГБ), видео — `ui.video_disk_mb`; в памяти — `ui.image_cache_mb` (128 МБ) | есть |
| Файл удалили или изменили во время загрузки | ошибка загрузки этой картинки со словами; редактор и текст остаются, можно приложить заново | есть |
| Ротация логов | новый файл каждый час и по размеру (`debug.log_mb`), всего не больше `debug.keep_mb` (500 МБ при отладке; без отладки 1 МБ на файл и 5 МБ всего, только предупреждения) | есть |

## 4. Интерфейс

| вопрос | ответ | решение |
|---|---|---|
| Блокируется ли главный поток | сеть и база — в фоновых потоках, в окно приходят только готовые ответы; отдельное соединение для чтения базы; сторожок пишет в лог фризы (при отладке). Бенчи меряют прокрутку и меню | есть |
| Мониторы с разным масштабом | Qt 6 и GTK 4 перерисовывают по масштабу монитора сами | есть |
| Размер и состояние окна | Qt запоминает геометрию и «развёрнуто»; GTK — размер (место окна на Wayland решает композитор) | есть |
| Монитор отключили | Qt при восстановлении переносит окно на видимый экран; GTK место не запоминает | есть |
| Смена светлой/тёмной темы системы | тема `system` берёт цвета рабочего стола при запуске; на ходу — после перезапуска или через ≡ → «Попробовать тему» | решать автору |
| Спам по кнопке «Отправить» | кнопка гаснет на время отправки во всех интерфейсах; сервер получает `Idempotency-Key`, повтор не создаст второй пост | есть |
| Навигация с клавиатуры | j/k, Enter, ←/→, Tab, горячие клавиши по всему окну; терминал — целиком с клавиатуры; подписи для экранного диктора | есть |
| 100 000 элементов | лента держит в окне не больше `feed.render_limit`, карточки строятся только для видимого участка; в базе — `keep_per_lane` на ленту | есть |
| Пустая строка, null, слово без пробелов | адаптер приводит поля к типам с безопасными значениями; длинные слова получают невидимые точки переноса (Qt, GTK), веб — `overflow-wrap: anywhere`; длинное описание картинки прокручивается | есть; описание — сделано в 0.20 |

## 5. Безопасность

| вопрос | ответ | решение |
|---|---|---|
| Где хранится токен | файл `auth.json` с правами 0600 в папке данных профиля; на Android — в личных данных приложения. Системное хранилище (Secret Service, DPAPI, Keychain) не используется — это давнее решение | решать автору |
| Токены и PII в логах | не пишутся: в лог идут метод, путь, параметры страниц и время; тело, текст постов и заголовки — нет. Отчёт об ошибке не берёт `auth.json` и базу | есть |
| Пароли в памяти | пароля fedtail не видит: вход через браузер (OAuth), в памяти только токен — строкой Python, как у любого клиента на Python | есть |
| Шифрование базы | нет: база в домашней папке пользователя, под правами его учётной записи. Шифрование (SQLCipher) — отдельная зависимость | решать автору |
| Инъекции | SQL только с параметрами; HTML с сервера чистится белым списком тегов; текст поста уходит в JSON | есть |
| Обфускация | нет: открытый код под GPL | есть |

## 6. Состояние и логика

| вопрос | ответ | решение |
|---|---|---|
| Удалили здесь, а там уже удалено | сервер ответит 404 — пост просто убирается и здесь, без ошибки | сделано в 0.20 |
| Оффлайн | черновики сохраняются сами; отметки о прочитанном копятся и уходят при связи (маркеры сервера и синхронизация между устройствами); пост без сети не отправится — останется в редакторе | есть |
| Конфликты синхронизации | Last Write Wins по каждому ключу: время и устройство в `sync_lww` | есть |
| Сон на 3 дня | круг сразу при пробуждении; отложенные посты и временные заглушки живут на сервере; чистка базы выполнится один раз | сделано в 0.20 (круг при пробуждении) |
| Гонки | база под блокировкой, чтение через отдельное соединение; события ядра доходят до окна через очередь главного потока | есть |

## 7. Установка и обновление

| вопрос | ответ | решение |
|---|---|---|
| Подлинность обновления | автообновления нет. Релиз на GitHub содержит `SHA256SUMS`; apt-репозиторий подписан ключом; exe подписывается сертификатом, если он задан; apk — ключом релиза | `SHA256SUMS` сделано в 0.20; ключи — решать автору |
| Атомарность обновления | установщик Inno Setup и dpkg откатывают незаконченную установку; данные профиля не трогаются | есть |
| Миграции базы | при старте добавляются недостающие столбцы; каждый шаг проверяет себя и повторяется при следующем старте, если не дошёл | есть |
| Миграция упала | следующий старт продолжит с того же места; данные не удаляются | есть |
| Откат на старую версию | старая версия работает с новой базой: столбцы только добавлялись | есть |
| Деинсталлятор | убирает программу и ярлыки; профиль в `%APPDATA%\fedtail` оставляет нарочно — это данные пользователя | есть |
| Обновление без прав администратора | установщик ставит в папку пользователя, права не нужны | есть |

## 8. Производительность и ресурсы

| вопрос | ответ | решение |
|---|---|---|
| Неделя без закрытия | лента ограничена `render_limit`, база чистится, кэш картинок в памяти — LRU с бюджетом. Проверка `tools/tabs_stress.py` (вкладки и «день работы»): память выходит на плато; в Qt остаётся мелочь — питоновские обёртки удалённых меню закрытых вкладок | есть |
| Кэш закрытых вкладок | закрытая вкладка отдаёт карточки и ссылки на них; картинки остаются в общем кэше до вытеснения по бюджету | есть |
| Батарея, пробуждения процессора | опрос раз в 90 с (или медленный режим), поток будит по событию; без отладки нет таймеров раз в секунду; Qt проверяет сигналы раз в секунду. Android — раз в 15 минут и пуш | сделано в 0.20 (таймеры) |
| GPU в свёрнутом окне | невидимое окно не рисуется ни в Qt, ни в GTK | есть |
| Логи и диск | файловый обработчик с буфером; без отладки — только предупреждения | есть |

## Что решать автору

| вопрос | варианты |
|---|---|
| Хранилище токена | оставить файл 0600; DPAPI на Windows без зависимостей; Secret Service через QtDBus на Linux |
| Шифрование базы | не шифровать; SQLCipher (зависимость и пароль при старте) |
| Автообновление | не делать (apt, магазин, ручная загрузка); проверка новой версии с подсказкой в меню |
| Прокси NTLM/Kerberos | документировать переходник; добавить `requests-ntlm` |
| Тёмная тема системы на ходу | применять сразу (Qt: `colorSchemeChanged`); оставить при запуске |
| Зависшая первая копия | ответ окна с таймаутом и предложение завершить старый процесс |
| Сертификат Windows, ключ apt | секреты `WINDOWS_CERT_PFX`, `APT_GPG_KEY` |
