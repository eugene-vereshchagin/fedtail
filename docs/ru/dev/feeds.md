# Свободные ленты: ленты, которые собираешь сам

**Статус: проект; шаг 1 (атомы, `core/atoms.py`) уже в коде** (27 окт 2026). Идея автора; здесь — во что она превращается в
fedtail, чего стоит и где кусается. Нынешние ленты описаны в [architecture.md](architecture.md) §8.

## 1. Идея

Сейчас лента — один источник плюс фильтр, написанный на Python (`core/lanes.py`). Свободная
лента — **несколько источников плюс правило из конфига**: пользователь называет, что в неё
идёт, из списка всего, что fedtail умеет различать в посте или событии, — *атомов*. Любая
лента может держать любые атомы: «новые посты моего сервера + ответы мне + мои посты» в одной,
«всё моё + ответы на мои посты» в другой.

Встроенные ленты остаются, но становятся заготовками, записанными теми же правилами. Что бы
пользователь ни собрал, пост, дошедший до fedtail и не попавший ни в одну ленту, не теряется:
он падает в **Неразобранное** (§6).

Атомы — не плоский список «типов»: пост одновременно и ответ, *и* мне, *и* только для
подписчиков, *и* с моего сервера. Поэтому атомы — **оси** (ключи), у каждой свои значения, а
правило их сочетает: внутри одного условия — И, между условиями — ИЛИ, плюс исключения.

## 2. Атомы: что можно различить

Каждый атом вычисляет ядро из того, что лежит в базе (статус, его уведомление, собственные
таблицы fedtail), никогда не фронтенд. Слова ниже — слова ядра: их заполняет протокол (§7).

### 2.4 Выведенные события (сверка снимков)

Того, что сервер клиенту не сообщает (отписка, снятый лайк, удалённый пост), в уведомлениях нет:
fedtail выводит это сам, сравнивая свою базу с тем, что сервер отдаёт сейчас. Раз в
`derived.interval_minutes` (по умолчанию 60) — снимок, разница с прошлым — событие.

| событие | что сверяем | цена | как не соврать |
|---|---|---|---|
| `unfollow` — от меня отписались | `accounts/<me>/followers`, весь список | страница на 40–80; 1000 подписчиков — 15–25 запросов | см. ниже |
| `removed_follower` — я сам убрал / заблокировал | то же | 0 (это моё действие) | не путать с `unfollow`: свои действия ядро записывает и вычитает |
| `moved` — подписчик переехал на новый аккаунт | поле `moved` у пропавшего | один `accounts/<id>` | не отписка: новый аккаунт подписывается сам |
| `gone` — аккаунт удалён / заблокирован сервером | ответ 404/410 на `accounts/<id>` | один запрос | не отписка, отдельное событие |
| `unfollowed_back` — я подписан, он больше нет (взаимность пропала) | пересечение с `following` | ещё столько же страниц | только вместе с `unfollow` |
| `unliked` — сняли лайк | `favourited_by` моих свежих постов | запрос на пост — дорого | только N последних постов за `derived.like_days` дней, по умолчанию выкл. |
| `deleted` — удалён пост, который у меня в базе | 404/410 при повторном получении | 0 (заметно по ходу) | пометка на карточке, не уведомление |

Защита от ложных отписок (главная беда таких фич):

* Снимок считается, только если список получен **целиком**: все страницы без ошибок, и число
  сходится с `followers_count` (± уже известные изменения). Иначе снимок выкидываем.
* Пропавший подтверждается: `relationships` должен сказать `followed_by = false`, и его нет в
  **двух** снимках подряд (сервер иногда отдаёт список с дырой).
* Сервер собеседника лежит или нас дефедерировал — массовое «отписались все с x.org»: больше
  `derived.mass_threshold` с одного домена за раз — одно событие «связи с x.org пропали», не сотня.
* Первый снимок — точка отсчёта, событий не даёт.
* Отписался и подписался обратно в пределах часа — не видно, и не надо.
* Две машины с синком видят одну отписку: ключ события — аккаунт + день, синк склеивает.
* Скрытые списки подписчиков (`hide_collections` у GoToSocial, «скрыть подписчиков» у
  Мастодона) владельцу обычно отдаются; если сервер отказал — событие выключается с пометкой в
  ≡ → Сведения о сервере.
* Опция: `derived.unfollow` (вкл./выкл.) — свой флаг, от `arts_mode` не зависит (решение
  автора, 25 окт 2026: `arts_mode` — про то, чего не показывать, а не про чувства).

## 3. Что достижимо, а что нет

Клиент фильтрует только то, что получил. Правило — обещание; эта таблица — что за ним стоит.

| хочется | откуда берётся | подвох |
|---|---|---|
| ответы мне | `mentions` | приходят, только если клиент автора меня упомянул (Mastodon и GoToSocial делают это по умолчанию) |
| ответы под моим постом, не мне | `subs` (мои треды подписываются сами) или `context` | `/context` на каждый тред при каждой проверке |
| новые посты моего сервера, читать подряд | `local`, опрашиваемый как `home` | `local` перестаёт быть ленивым: запросы каждый опрос |
| что пишут подписки незнакомцам | — | home Мастодона выкидывает ответы тем, на кого я не подписан; только через `account:<id>` |
| весь федиверс | — | `federated` — только то, что знает мой сервер |
| бусты моего поста как посты | `event = "reblog"` | «поста» буста моего в лентах нет — только событие |
| кто прочитал / увидел | — | в ActivityPub этого нет вообще |
| unlisted-посты незнакомцев | `account:<id>`, `context`, поиск | в публичных лентах их нет по определению |
| followers-only тех, на кого я не подписан | — | сервер мне их никогда не отдаст |
| правки поста, который никто не бустил | сам пост, когда его снова получили | события нет; `kind = "edited"` видно, когда пост пришёл снова |

## 4. Правила в конфиге

Свободная лента — таблица `[[lanes.custom]]`; её ключи:

| ключ | смысл |
|---|---|
| `name` | слово ленты (неизменное: окно, синк и плитки помнят ленты по нему) |
| `title` | что показывает боковая панель; без title — слово |
| `any` | список условий: пост входит, если подходит под **любое**; внутри условия должны совпасть все ключи (И), список значений — любое из них |
| `none` | условия, которые не пускают пост, даже если `any` пустило |
| `source` | сужает все условия до этих источников; без `source` ядро само берёт источники, которые могут принести атомы (§3) |
| `sort` | `arrival` (когда дошло до нас) или `post_time` (время самого поста; ленты с уведомлениями) |
| `read` | `through` (метки непрочитанного, счётчики, без прыжков) или `browse` (свежая страница, без счётчиков — как Федеративная) |
| `group` | раздел боковой панели: `standard`, `personal`, `lists`, `tags` или своё имя |
| `switch` (у условия) | условие-переключатель: чип над лентой с этим словом; `shown = false` — по умолчанию скрыто (как нынешнее «только посты») |

Две ленты автора из первого разговора:

```toml
[[lanes.custom]]
name = "feed"
title = "Лента"
any = [
  { author = "local", kind = "post" },        # новые посты моего сервера
  { me = "reply" },                            # ответы мне
  { author = "me" },                           # мои посты
]

[[lanes.custom]]
name = "home_plus"
title = "Лента"
any = [
  { source = "home", kind = "post" },                               # посты
  { source = "subs" },                                              # подписки на треды
  { source = "home", kind = "reply", switch = "Комменты", shown = false },  # скрывается
]

[[lanes.custom]]
name = "posts"
title = "Посты"
any = [
  { author = "me" },                           # всё моё, всем
  { me = "reply_to_post" },                    # ответы мне на мои посты
]
none = [{ kind = "boost", age = ">2d", age_of = "original" }]   # старьё, поднятое бустом, — нет
```

## 5. Как это себя ведёт

* **Один пост — много лент.** Пост может лежать в нескольких лентах; это **один** пост:
  прочитал в одной — прочитан везде (и синкается). Буст и оригинал — тоже один пост
  (`feed.dedupe_boosts`, уже в планах опцией).
* **Источники из правил.** `lanes.sources_needed()` считается из правил: объединение
  источников, нужных каждому условию. Источник, не нужный ни одной ленте, не тянем.
* **Ленивая или нет.** Лента с `read = "through"` заставляет свои источники опрашиваться через
  `catch_up`, даже `local`; ленты `browse` тянут источники только пока открыты.
* **Порядок.** Решает `sort`; лента, смешивающая уведомления и ленты, по умолчанию сортирует
  по времени поста (опоздавшее встаёт на своё место, выше разделителя, если прочитано).
* **Что раньше.** Блокировки, заглушки, серверные фильтры «скрыть» и скрытые участники списков
  применяются **до** правил: никакое правило не вернёт заглушённого.
* **Уведомления и звуки** — один раз на пост, по самой личной ленте, куда он попал
  (личка > ответ > упоминание > тред > остальное), а не по разу на ленту.
* **Переключатели** (`switch`) — чипы над лентой, как нынешний «только посты»; состояние
  помнится на ленту и синкается. Скрытое переключателем лента всё равно *взяла*: в
  Неразобранное оно не идёт, счётчик и уведомления его не считают, при включении встаёт на своё
  место, а место чтения не двигается. Нынешние `posts_only`, `mentions_all`, `direct_apart`
  становятся переключателями заготовок.

## 6. Умолчания и лента «Неразобранное»

Встроенные ленты становятся заготовками на правилах; их слова остаются (и старые —
`lanes.RENAMED`). Кто не пишет ни одной `[[lanes.custom]]`, видит ровно то же, что сейчас.

| заготовка | правило |
|---|---|
| `home` | источник `home`, `none = [{ author = "bot" }]` |
| `bots` | источник `home`, `any = [{ author = "bot" }]` |
| `my_posts` | `any = [{ author = "me" }]` |
| `direct` | `any = [{ me = "direct" }]` |
| `replies` | `any = [{ me = "reply" }]`, не мои |
| `mentions` | `any = [{ me = "mention" }]` |
| `subs` | источник `subs`, не `me = "reply"` |
| `activity` | `any = [{ event = ["favourite", "reblog", "follow"] }]` |

* **Неразобранное** (`unsorted`) — всё из источников, *читаемых подряд*, что не взяла ни одна
  лента. Появляется, только когда в нём что-то есть, и в подсказке говорит, какое правило было
  ближе всего («Почему оно здесь?»). Источники для просмотра (`federated`, `local`, пока
  ленивый) туда не идут: утопят.
* После смены правил то, что уже лежит в базе, раскладывается заново; ничего не перекачиваем.

## 7. Протоколы и новые атомы

* Атомы — слова ядра (`core/atoms.py`), протоколы их заполняют. Каждый протокол говорит, какие
  атомы умеет (`Capabilities.atoms`); условие на атом, который сервер не заполняет, никогда не
  срабатывает, а ≡ → Сведения о сервере показывает такие ленты как «здесь не заполнить», а не
  молча пустыми.
* Новые сырые типы приходят с обновлениями: у атома есть `since` (версия), пример конфига и
  `docs/src/features`. Неизвестный ключ или значение в конфиге — предупреждение в логе и
  пометка на ленте, никогда не падение и не молча пустая лента.
* Атомы только Мастодона (`quote`, `severed`) GoToSocial просто не заполняет; Matrix и прочие
  заполнят, что у них есть (бустов там, например, нет).

## 8. Проблемы подхода

Кроме «настройка становится программированием»:

| проблема | почему кусается | что делаем |
|---|---|---|
| Лента обещает то, чего не даёт ни один источник | «ответы подписок незнакомцам», «весь федиверс» выглядят записываемыми и остаются пустыми | §3 как проверка: условие, которое не заполнит ни один источник, — предупреждение и пометка на ленте |
| Бюджет запросов | каждый `local` подряд, каждый `in_my_thread` (`/context` на тред) тратят 300 запросов сервера за 5 минут | счёт запросов по лентам в логе и в ≡ → Сведения о сервере; `context` — только для подписанных тредов, как сейчас |
| Чистка по источникам | `prune` держит N элементов на **источник**; лента из нескольких источников может потерять хвост, пока другой не хватает | держать по лентам (самый старый элемент, который ещё показывает хоть одна лента), бюджет — те же 1 ГБ |
| Дыры в чтении подряд | у ленивого источника есть дыры; в ленте «подряд» это ломает «ничего не пропущено» | источник в ленте «подряд» всегда догоняется целиком; лента пишет об этом в лог |
| Атомы, известные поздно | `reply_to_post` против `reply_to_comment`, `parent`, `in_my_thread` требуют родителя или тред, их тянем в фоне | пост ждёт «разбирается» (секунды) и показывается, когда известно; без ответа — по тому, что известно, и после показа уже не прыгает |
| Атомы, которые меняются | снятый лайк, закладка, отписка (`followed` → `stranger`), правка с добавленным CW задним числом двигают посты между лентами | показанный пост остаётся до переоткрытия ленты; счётчики пересчитываются, место чтения не двигается |
| Дубли | один пост из `home`, `local` и `mentions`; буст и оригинал | одна карточка на пост в ленте; какой контекст показать (цитата родителя, «бустнул») — из самого личного источника |
| «Прочитать всё» сквозь ленты | прочитанное в узкой ленте прочитано во всех, и широкая теряет непрочитанное | ожидаемо, как на Point; опцию «прочитано только в этой ленте» не планируем — ломает синк |
| Шторм уведомлений | пост в трёх лентах — три звука | один раз на пост, по самой личной ленте (§5) |
| Неразобранное переполняется | широкий источник, который не берёт ни одно правило (federated подряд), его топит | Неразобранное берёт только источники «подряд»; больше N элементов — подсказка, какой источник топит |
| Опечатки | `me = "replys"` — лента молча пустая | строгая проверка на старте: неизвестные ключи и значения — предупреждение и пометка; `fedtail --explain-lane ИМЯ` и «Почему оно здесь?» на карточке |
| Цена правил | каждая лента × каждый элемент в базе на каждом обновлении: тысячи × десятки | атомы считаются один раз на пост и хранятся (кэш по `status_version`); правило — проверка нескольких битов |
| Имена и синк | окно, колонки, плитки, синк и `notify.lanes` помнят ленты по слову; переименованная лента всё это теряет | `name` — это id, не меняется; `title` — свободно; смена `name` — как `RENAMED` в 0.15 |
| Старые переключатели | `mentions_all`, `direct_apart`, `posts_only`, `lists.hide_in` пересекаются с правилами | остаются сокращениями для заготовок; своя лента их не получает, её правило говорит всё само |
| Ленты и события вперемешку | строка лайка — не пост: нет треда, ответа, другая карточка, другое «прочитано» | можно, но лента с событиями считает только посты; события — своё «просмотрено» Активности |
| Четыре интерфейса и Android | каждый должен рисовать любую ленту и разделы панели; на телефоне конфиг неудобен | ленты приходят из ядра уже собранными (как сейчас); в странице настроек Android редактор лент — позже |
| Лента между профилями | `author = "me"` во втором профиле — другой человек; «мои другие аккаунты» требуют мультиаккаунта | по профилям, как конфиг; `my_accounts` — когда одно окно держит несколько аккаунтов |
| Протокол уезжает | атомы скроены по Мастодону; в другой сети может не быть ни бустов, ни видимости | `Capabilities.atoms` (§7); лента говорит «здесь не заполнить» |

## 9. Шаги

1. `core/atoms.py`: каждый атом из §2 — функция от поста в базе (и таблиц fedtail), тесты на
   каждый на `tests/fakes.py`; атомы хранятся у поста.
2. Правило: разбор, строгие проверки, `explain`; тесты на каждый ключ и каждую ошибку.
3. Встроенные ленты как заготовки: тот же результат, что `LANES` сейчас, элемент в элемент
   (тест на записанной базе).
4. Ленты из нескольких источников: `lane_entries`, `sources_needed`, чистка по лентам, `local`
   подряд.
5. Неразобранное, «Почему оно здесь?», `--explain-lane`.
6. Конфиг (`[[lanes.custom]]`, оба примера), `docs/src/features`, справка.
7. Интерфейсы: боковая панель, колонки, плитки, уведомления по самой личной ленте; паритет в
   `docs/src/parity.toml`.
