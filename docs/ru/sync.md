# Синхронизация между устройствами

[In English](/docs/en/sync.md)

fedtail на десктопе, на ноутбуке, потом и на телефоне — один аккаунт, одно прочитанное.
Прочитал пост на одном — прочитан на остальных; подписался на тред, вышел из него или
заглушил, передвинул список в боковой панели — так и везде.

Синхронизация — **отдельный сервис**, не твой сервер федиверса: fedtail синхронизируется,
только если ты сказал куда (`sync.url` или `sync.folder`). Без этого синхронизации нет —
в строке статуса «⇅ нет», в «О программе» написано почему.

Что синхронизируется — по переключателю на каждое в `[sync]` (по умолчанию всё включено;
выключено — остаётся только на этом устройстве):

| переключатель | что это | как два устройства договариваются |
|---|---|---|
| `sync.read` | отметки прочитанного, которые сделал **ты**: прокрутка, открытие, «прочитать всё» | отметка не отменяется, так что они просто складываются |
| `sync.threads` | тред, на который ты подписался, из которого вышел или который заглушил руками | побеждает самое свежее действие |
| `sync.lanes` | твои ленты, как ты их расставил: порядок списков (серверы его не хранят, и каждое устройство показало бы их как пришли) и сохранённые ленты тегов | побеждает самая свежая расстановка |
| `sync.drafts` | черновики: начал на одном устройстве, дописал на другом; отправил или стёр — пропал везде. Текст, предупреждение, опрос, кто увидит; картинки — файлы конкретного компьютера и остаются там, где их добавили | побеждает самая свежая версия черновика |
| `sync.activity` | уведомления, которые ты убрал из «Активности» | только складываются, как отметки прочитанного |
| `sync.tiles` | какие ленты закреплены плитками на телефоне | побеждает самый свежий набор |

Что остаётся на каждом устройстве: отметки, которые fedtail ставит сам (всё прочитано при
первом запуске, старая история, свои посты), автоматические подписки на свои посты (их
делает каждое устройство), сами посты, конфиг. Новый телефон не прочитает за тебя
непрочитанное на десктопе.

Короткие имена постов (`#kq3zt`) одинаковые на всех устройствах и без этого: они
выводятся из id поста.

## Как это устроено

Каждое устройство ведёт журнал своих действий и отправляет его, зашифрованным, туда, куда
дотягиваются все твои устройства; оттуда же забирает журналы остальных. Это место —

* **сервер fedtail-sync** — маленькая программа на своём собственном адресе (`sync.url`); или
* **папка**, которую видят все устройства, — шара на NAS, примонтированный WebDAV
  (davfs2, rclone), папка Syncthing.

Журналы зашифрованы (AES-256-GCM) ключом, который есть только у твоих устройств. Сервер
или папка видят непрозрачные куски данных: кто прислал, какого размера, когда — но не что
ты читал и не какие треды. Потерял все устройства с ключом — потерял только отметки
прочитанного: восстановить их нельзя, да и ценность у них небольшая.

Серверу синхронизации fedtail никогда не отдаёт свой токен — тот открывает весь аккаунт.
`fedtail sync login` просит у твоего сервера федиверса второй, ограниченный
`read:accounts`: им можно только узнать «кто я». Сервер синхронизации проверяет его у
твоего сервера и складывает журнал под этим именем — своих аккаунтов и паролей у него нет.

## Как включить

В конфиге каждого устройства — одна строка, адрес, который дал админ сервера:

```toml
[sync]
url = "https://sync.example.org"
```

или вместо сервера — папка, которую видят все устройства:

```toml
[sync]
folder = "~/Sync/fedtail"
```

Сам fedtail ничего не ищет: нет адреса — нет синхронизации.

С **сервером синхронизации** — на каждом устройстве, один раз:

```sh
fedtail sync login      # откроется страница твоего сервера: разреши «fedtail sync», вставь код
```

**Ключ** делает первое устройство при первой синхронизации. Покажи его там и перенеси на
остальные (руками, через менеджер паролей, QR-приложением — это секрет: у кого есть ключ
и твой токен, тот прочтёт журнал):

```sh
fedtail sync now        # на первом устройстве: делает ключ, отправляет, что есть
fedtail sync key        # показывает его: XXXX-XXXX-…
fedtail sync join XXXX-XXXX-…   # на каждом другом устройстве
```

`fedtail sync status` — куда синхронизируется, id ключа, что ждёт отправки и как прошёл
последний раз. Окно синхронизируется само раз в `sync.interval_seconds` и через несколько
секунд после того, как ты что-то прочитал. Справа в строке статуса видно, как дела:
«⇅ 21:40» — синхронизировано тогда (под мышкой — куда, сколько ушло и пришло), «⇅ …» —
ещё не было, «⇅ !» — проблема (под мышкой — какая), «⇅ нет» — в конфиге нет адреса. То же
одной строкой — в «О программе».

Устройство без ключа, которое находит там чужой журнал, свой ключ не делает: просит
`fedtail sync join`.

## Свой сервер fedtail-sync

Это один файл на стандартной библиотеке: [`syncserver/fedtail_sync.py`](/syncserver/fedtail_sync.py)
(Python 3.11+, SQLite). Скопируй его на сервер — больше ничего от fedtail там не нужно.

Своя папка, например `/srv/fedtail-sync/`, — в ней файл, его конфиг и база; системный
пользователь для него:

```sh
sudo useradd --system --no-create-home --shell /usr/sbin/nologin fedtail-sync
sudo mkdir -p /srv/fedtail-sync
sudo cp fedtail_sync.py /srv/fedtail-sync/
sudo chown -R fedtail-sync: /srv/fedtail-sync
```

`/srv/fedtail-sync/config.toml`:

```toml
listen = "127.0.0.1:8471"
db = "/srv/fedtail-sync/sync.db"
instances = ["your.server"]   # whose people are served; ["*"] — anyone's (public servers only)
quota_mb = 20                 # per account; a year of reading is a few MB
max_blob_kb = 512
requests_per_minute = 120     # per account
keep_days = 0                 # 0: kept until the account deletes its journal
total_mb = 1024               # all accounts together; 0 — no cap
timeout_seconds = 30          # a silent connection is dropped (a whole request: twice that)
max_connections = 64          # served at once; more are closed at the door
requests_per_minute_per_ip = 240
verifications_per_minute_per_ip = 10   # token checks at a fediverse server, per address
verifications_per_minute = 60          # ... in all
client_ip_header = "CF-Connecting-IP"  # behind cloudflared/nginx on this machine; "" — none
```

Юнит systemd, `/etc/systemd/system/fedtail-sync.service`:

```ini
[Unit]
Description=fedtail-sync
After=network-online.target
Wants=network-online.target

[Service]
ExecStart=/usr/bin/python3 /srv/fedtail-sync/fedtail_sync.py --config /srv/fedtail-sync/config.toml
User=fedtail-sync
NoNewPrivileges=true
ProtectSystem=strict
ProtectHome=true
PrivateTmp=true
ReadWritePaths=/srv/fedtail-sync
Restart=on-failure

[Install]
WantedBy=multi-user.target
```

```sh
sudo systemctl daemon-reload && sudo systemctl enable --now fedtail-sync
curl -s http://127.0.0.1:8471/v1        # {"fedtail-sync": 1}
```

Говорит он обычным HTTP на localhost; TLS делается перед ним, на его собственном имени
(например, `sync.твой.домен`) — сервер федиверса не трогаем.

**Cloudflare Tunnel** (туннель из дашборда): Zero Trust → Networks → Tunnels → твой
туннель → Published application routes (Public Hostname) → добавить: поддомен `sync`,
твой домен, путь пустой, сервис `http://127.0.0.1:8471`. Именно `http`, а не `https`
(TLS делает Cloudflare), и `127.0.0.1`, а не `localhost` (тот может уйти в IPv6, где
сервер не слушает). DNS-запись появится сама. Если туннель настроен файлом — то же
правилом ingress:

```yaml
  - hostname: sync.your.domain
    service: http://127.0.0.1:8471
```

**nginx** — отдельный `server { … }`:

```nginx
server {
    server_name sync.your.domain;
    # listen / ssl_certificate — как у остальных твоих сайтов
    location / {
        proxy_pass http://127.0.0.1:8471;
        client_max_body_size 1m;
    }
}
```

**Caddy**:

```
sync.your.domain {
    reverse_proxy 127.0.0.1:8471
}
```

Проверка снаружи: `curl -s https://sync.твой.домен/v1` → `{"fedtail-sync": 1}`. Твои
люди пишут этот адрес в `sync.url` и делают `fedtail sync login`.

### Как он себя защищает

Он смотрит в интернет, поэтому все ограничения включены по умолчанию (значения выше — и
есть умолчания, кроме `client_ip_header`):

| что можно попробовать | что этому мешает |
|---|---|
| открыть соединения и молчать или слать по байту раз в полминуты | обрыв после `timeout_seconds` тишины; на весь запрос — вдвое больше |
| открыть тысячи соединений | одновременно не больше `max_connections`, остальные закрываются сразу |
| завалить запросами | `requests_per_minute_per_ip` на адрес, `requests_per_minute` на аккаунт |
| слать случайные токены, чтобы сервер долбил проверками чей-то сервер федиверса | известному токену верит 10 минут, отказанный отказан минуту; настоящие проверки ограничены на адрес и всего (`verifications_per_minute_per_ip`, `verifications_per_minute`) |
| врать в `Content-Length`, не указывать его, слать кусками (chunked) | отказ до чтения (411, 400, 413); тело короче обещанного не держит поток |
| забить диск | `quota_mb` на аккаунт и `total_mb` на всех (с `"*"` любой со своим сервером может наплодить аккаунтов) |
| заставить его сходить в твою локалку (с `"*"`) | только публичные адреса, проверка на уже открытом соединении — имя, сменившее адрес между проверкой и запросом, ловится; за редиректами не ходит, так что токен никуда больше не уходит |
| выведать его внутренности | ошибка внутри отвечает «internal error», подробности — только в его лог |

**За прокси на той же машине** — cloudflared, nginx, Caddy — все запросы приходят с
127.0.0.1, и лимиты на адрес считали бы весь мир одним клиентом. Укажи в `client_ip_header`
заголовок, куда прокси кладёт настоящий адрес: `CF-Connecting-IP` у Cloudflare, `X-Real-IP`
у nginx с `proxy_set_header X-Real-IP $remote_addr;`. Ему верят только от локального
соседа и только если в нём адрес — клиент так лимит не обойдёт. Если слушать не на
127.0.0.1, сервер при старте предупредит: он говорит обычным HTTP.

Тесты на каждое из этого — в `tests/test_syncserver_security.py`; CI гоняет их вместе с
bandit на каждый пуш, и без них релиз не выйдет.

Что хранит сервер: для каждого аккаунта (его id на его сервере) — зашифрованные куски со
случайным id устройства и временем. Что пишет в лог: строку на запрос — адрес, путь,
ответ, — никогда не токен. `DELETE /v1/blobs` с токеном аккаунта удаляет весь его журнал.

### Люди с других серверов

`instances = ["*"]` обслуживает любого, чей сервер подтвердит токен (только публичные
адреса: в твою локальную сеть сервер никогда не ходит). Журналы зашифрованы, так что это
стоит места на диске и трафика, а не приватности; квота и лимит запросов держат это
маленьким. Бета-тестер с другого сервера прописывает в конфиге тот же
`url = "https://sync.твой.домен"`.

## Чего пока нет

* Переноса ключа QR-кодом из окна (сейчас — `fedtail sync key` / `join`).
* Картинок черновика, переезжающих вместе с ним (сейчас — остаются на устройстве, где их добавили).
* WebDAV напрямую (сейчас — примонтированный как папка).
* Упаковки старых журналов в снимок (сейчас они просто копятся, в пределах квоты).
